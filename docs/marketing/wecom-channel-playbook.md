# 微信客服按入口分码 · 欢迎语 · 来源区分操作手册

> 最后更新：2026-09-16（v1.37.4）
> **适用对象**：本项目的活码 = 企微后台「**微信客服**」里创建的**客服账号**链接（`work.weixin.qq.com/kfid/...`），
> **不是**「客户联系」的加好友活码。这两条线的能力不一样，别按加好友那套去后台找。
> 本文件只回答一个问题：**怎么知道眼前这个客户是从「留资弹窗 / 分享图 / 落地页」哪一个来的**。
> 站点侧的一半（按入口取不同的码）已在 v1.37.3 上线；本文件是**企微后台那一半**。
> 配套：执行清单见 [gtm-execution-plan.md](gtm-execution-plan.md)，线索跟进见其「线索跟进 SOP」一节。

## 结论先行（都核实过，不是猜的）

1. **你这个能分来源。** 官方《如何使用微信客服》：一个微信客服可建 **5000 个客服账号**，并建议
   "一般一个客服账号可用于一个业务线"；每个账号有**独立的接入链接**（`kfid/` 后即客服账号 ID）。
   → **一入口一账号一链接，是官方支持的用法**。
2. **不要手工给链接拼 `?from=share`。** 官方《获取客服账号链接》：客服链接**不可改写、参数不可复制到其他链接**，
   否则「用户进入会话事件」参数校验失败、无法回调 —— 页面照开，但**回调里拿不到来源**。
   （"带参数的客服链接"确实存在，但只能由 **API** 生成，见第 4 节，冷启动不必做）
3. **微信客服没有「扫码自动打标签」。** 帮助中心里的"自动打标签 / 渠道活码"属于**客户联系**（加好友）那条线，
   微信客服的客户不是外部联系人好友。**所以来源区分靠"哪个客服账号接的"，不靠标签** —— 这已经够用，
   标签只是把来源固化到客户身上（替代做法见第 4 节）。
4. **欢迎语有，而且能按账号分别配。** 官方《如何设置微信客服欢迎语》：一个企业可配 50 条欢迎语，
   **一条欢迎语可关联多个客服账号，一个客服账号同一时间只能关联一条** —— 这正好是"按入口说不同的话"的官方路径。

> 想换成（或并用）**「客户联系」加好友活码**？那是一条不同的线，见第 5 节 B 方案 —— 它能打标签，
> 但欢迎语是**按成员**生效（一个人只有一句），且客户要加你为好友。

## 站点侧已具备的能力（v1.37.3 已上线）

配置在 `index.html` 底部的 `window.LEAD_CONFIG`：

| 字段 | 触发的入口 | 说明 |
|---|---|---|
| `wecomQrUrl` | 兜底 | 所有未单独配置的入口都用它；留空则弹窗降级为仅留言通道 |
| `wecomQrByChannel.modal` | 站内留资弹窗（结果页 / 个人中心） | 未配 → 回落兜底码 |
| `wecomQrByChannel.share` | 分享图带来的访客 | 分享图上的码仍是"回流站点"的码（它负责拉新访问），
访客进站后归因记为 `share`，**其留资弹窗改用这个专属码** |
| `wecomQrByChannel.landing` | 站外落地页 / SEO 页（`source` 含 `seo_` / `landing`） | 未配 → 回落兜底码 |

- 入口归类见 `lead-modal.js` 的 `channelOfSource()`：复用后端已认可的 `source` 字符串，**不新增归因字段** ——
  管理台线索表的 `source` 与企微侧的客服账号是同一套来源口径，两边对得上。
- 未配置或配空白串的入口一律回落兜底码：**少配一个入口不会让通道消失**，只会少一条来源数据。

## 后台三步（路径：管理后台 → 应用管理 → 微信客服）

> 菜单层级以你后台实际界面为准；下面是"做什么"，不是"点第几级"。

### 第 1 步：再建客服账号，一个入口一个

| 入口 | 建议账号名 | 链接填到 |
|---|---|---|
| 留资弹窗 | 顾问-入口-留资弹窗 | `wecomQrByChannel.modal` |
| 分享图带来的访客 | 顾问-入口-分享图 | `wecomQrByChannel.share` |
| 站外落地页 / SEO 页 | 顾问-入口-落地页 | `wecomQrByChannel.landing` |

- 取链接：客服账号详情页 → **接入链接**（`https://work.weixin.qq.com/kfid/...`）。
- **建议第一步只建 `share` 这一个**：你现在这个账号继续当兜底码（供留资弹窗与所有未配入口使用），
  现有分享图与已发出的链接**一个都不用动**，风险为零；验证通了再补 `landing`。

### 第 2 步：欢迎语按账号分别配（官方路径）

入口：管理后台 → 应用管理 → 微信客服 → **欢迎语** → 配置 → 添加 / 编辑（或手机端/电脑端 工作台 → 微信客服 → 欢迎语）。

三份文案（**要有差异**，一模一样等于没分）：

- **留资弹窗**："您好，这里是 EuriskoTax 顾问。您刚在测算页留了信息 —— 直接把想核对的问题发过来就行，我会结合您的测算类型给您答复（不采集收入金额）。"
- **分享图**："您好，您是通过朋友分享的测算结果找到我们的。想核对哪一项？把情况发我，我按您所在城市的口径帮您看一下。"
- **落地页**："您好，您是从我们的个税文章过来的。文章里没讲到的情形可以直接问我，比如年终奖计税方式怎么选、专项附加扣除漏填怎么补。"

合规约束：不承诺"一定能退税 / 一定少缴"，统一用"核对 / 测算 / 参考"。

**四个官方坑（不写进去你一定会踩一个）**：

| 坑 | 官方原文要点 | 怎么办 |
|---|---|---|
| 48 小时 | 同一微信账号 48h 内收过欢迎语就不再发；改了欢迎语后同账号要等 48h 才生效 | **验收时换个微信号扫**，否则你会以为没配好 |
| 一条对一账号 | 一个客服账号同一时间只能关联一条欢迎语 | "按入口分"就是三个账号关联三条 |
| API / 第三方授权 | 若账号开了 API 或授权第三方分配会话权限，**原生欢迎语不生效且不可更改** | 我们暂时别开 API 分配会话 |
| 欢迎语带链接 | 带链接需客服组件支持，否则发不出去 | 上面三份文案**别带链接** |

### 第 3 步：接待人与接待时间（顺手把 P0 #4 落地）

每个客服账号可单独配：接待人员、**分流规则**（轮流 / 空闲 / 优先分配给上次接待人员）、**接待时间**
（默认全天 24 小时，可自定义；非接待时间客户进排队）。

- 建议：把接待时间设成你真能回复的时段，其余时段交给站点的**留言通道**兜底（已上线）—— 这正好是
  Go/No-Go 里 P0 #4「顾问值班人与响应时限」的工程化落法。
- 注意：**只有已激活且已实名**的成员才会收到客户分配；未实名成员设了也接不到。

## 来源怎么看出来（不靠标签也成立）

1. **客服账号本身就是来源**：后台按账号看会话与客户 —— 哪个账号进来的，就是哪个入口来的。
2. **站点侧对得上**：埋点 `euriskotax:lead-click` 带 `wecomChannel`，线索库 `source` 同口径，两边可以互相核对。
3. **想把来源固化到客户身上**（锦上添花，冷启动不必）：
   - **不同账号配不同接待人** —— 人即标签，零成本；
   - 在欢迎语里问一句，由顾问**手工补标签**；
   - 或走**高级路径**：用《获取客服账号链接》API 生成带 `scene`（≤32 字节，`[0-9a-zA-Z_-]`）的链接，
     「用户进入会话事件」回调会原样带回 `scene` —— 我们有 Node 后端与线索库，将来可以把来源回写到自己的库里。
     代价：要 `access_token` 与微信客服 API 权限。等三个入口的量真的值得自动化时再做。

## 5 · B 方案：客户联系「联系我」活码（加好友）

官方路径（原文）：**管理后台 → 客户与上下游 → 客户联系 → 加客户 → 联系我** → 新建联系方式。

### 建码四步

| 步骤 | 怎么选 |
|---|---|
| 联系形式 | 选**二维码**（另两种是工卡、小程序按钮） |
| 类型 | **单人**（扫了就是你）／**多人**（活码，最多 100 名成员，客户随机分到其中一位）／**批量单人**（一次给多人各出一张）<br>你一个人接待 → 单人；想以后加人不用换码 → 多人（先把自己放进去） |
| 添加设置 | 勾「**客户添加时无需经过确认自动成为好友**」（官方：默认勾选）→ 免确认，转化更高 |
| 备注 | 写来源名，如 `来源-留资弹窗` —— 后台里唯一好认的标识 |

建完：列表里**下载**二维码。官方文档只写了"下载"；**后台同处一般还有「复制链接」**（以后台实际为准）——
有链接就优先用链接（换人不用换图）。数量上限：单人 + 多人类二维码合计 **1000 个**，够用。

### 填进站点（两种形态都收）

| 后台产物 | 填到 `wecomQrByChannel.*` | 站点行为 |
|---|---|---|
| 链接（`work.weixin.qq.com/ca/...`） | 直接填 | 现场生成二维码（推荐） |
| PNG 图片 / 企微图床地址 | 直接填 | 当图片显示（`lead-modal.js` 已识别 `.png` 与 `wework.qpic.cn`） |

### 三个坑

| 坑 | 官方口径 | 后果 |
|---|---|---|
| **欢迎语按成员生效** | 「每个成员仅生效一条欢迎语」，最多 100 条、每条 1000 字、附件 ≤9 个 | 三个码都指向你一个人 → 客户听到的都是同一句，**做不到"一入口一句"**（这是与微信客服最大的差别） |
| **自动打标签：官方帮助页没背书** | 《如何添加客户》《联系我》《客户标签》三篇官方页**均未写**「联系我」自动打标签 | 新建表单里若看到「自动打标签 / 标签」就选上；没有就在客户添加后手工打，或用不同接待人区分 |
| **前置权限** | 成员需在「客户联系 → 配置 → 使用范围」内，且**已激活 + 已实名** | 否则客户加不上、或加了没人接 |

企业客户标签建在：管理后台 → 客户与上下游 → 客户联系 → **企业客户标签**（上限 100 组 × 100 个，标签名 ≤30 字符）。
建议建一个「来源」标签组：留资弹窗 / 分享图 / 落地页。

### 两条线怎么选

| | 微信客服（你现在用的 kfid） | 客户联系活码（加好友） |
|---|---|---|
| 用户动作 | 扫码直接进会话，**不用加好友** | 扫码**加你为好友** |
| 转化门槛 | 低（冷启动更友好） | 略高，但加了就是长期资产 |
| 来源区分 | 按**客服账号**（后台天然分） | 按**码的备注** + 标签 |
| 欢迎语颗粒度 | **按账号**，可一入口一句 | **按成员**，一人只有一句 |
| 自动打标签 | ❌ 无 | 部分（以后台为准，官方未背书） |
| 关系持续性 | 会话制，有 48h 规则 | 好友关系长期有效，可后续触达 |

**建议并存，不要替换**：留资弹窗继续用微信客服（门槛低、即时咨询），分享图 / 落地页用加好友活码（沉淀长期关系、可打标签）。
站点侧本来就按入口填不同的码，**两套可以同时填**。

### 待办（下次动活码时一并处理）

- [ ] **拿到「联系我」的复制链接就换回链接形态**：企微后台 → 客户联系 → 加客户 → 联系我 → 看该码有没有
      **「复制链接」**（官方文档只写了"下载"，以后台实际为准）。有的话把 `wecomQrByChannel.share / .landing`
      从 `images/weworkQR.png` 换成这个链接 —— 桌面端点击可直达加好友页，以后换人也不用换图
- [ ] 没有链接就维持图片形态：扫码完全正常，唯一差别是**点击只能打开这张图**（手机上长按可识别）

## 验证清单（建完必须做，约 10 分钟）

1. 两个码各扫一次，**用两个不同的微信号**（规避 48h 坑）→ 是否进入两个不同客服账号的会话？
2. 两条欢迎语是否分别触发（不是同一句）？
3. 站点侧：桌面端打开留资弹窗 → devtools 看 `#lead-wecom-link` 的 `href`，应为该入口的专属链接。
4. 分享图路径：生成一张分享图 → 扫它上面的码进站（URL 带 `?source=share`）→ 打开留资弹窗 →
   二维码应变成 `share` 账号的链接。
5. 兜底：把某个入口的码清空 → 该入口应回落到兜底码，**通道仍然可用**（不出现空白或裂图）。

## 常见错误

| 错误 | 后果 |
|---|---|
| 手工给链接拼 `?from=xxx` | 页面照开，回调拿不到来源（见结论 2） |
| 只建一个账号却指望分出来源 | 企微侧无从判断，数据永远是"总数" |
| 三个账号关联同一条欢迎语 | 统计分开、体验没分开，客户感知不到差异 |
| 用同一个微信号反复验收欢迎语 | 撞 48h 规则，误判"没生效" |
| 一次换掉全部码并立刻停用旧码 | 已发出去的分享图 / 文章里的旧码失效，且无法回溯；旧码至少留一个迭代周期 |
