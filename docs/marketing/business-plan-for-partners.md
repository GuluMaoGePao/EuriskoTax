## 一、一页纸摘要

### 我们是谁

我们有**真实的会计/税务申报服务能力**（这是我们区别于所有竞品的根本）。
EuriskoTax 是我们自建的**免费个税测算工具**，它的角色不是"卖软件赚钱"，而是：

> **用免费工具获取高商业意图流量 → 把其中能付得起服务费的人群转成线索 → 由我们的财税服务能力完成交付与成交。**

### 2.2 产品铁律（对外承诺，也是护城河）

1. **计税能力永不锁定** —— 免费版就能算全部税种，锁定的是云端增值（同步 / 报告 / 多设备）。锁定计算能力会毁口碑。
2. **计算永远在前端** —— 云端只做账号、同步、统计、运营。这带来隐私卖点、离线可用、服务器成本≈0。
3. **不做广告** —— 财务工具的信任就是产品本身。
4. **不做申报，只做测算** —— 所有页面统一免责声明；服务交付由持牌/合规的服务团队完成。
5. **合规即卖点** —— 文案禁用"避税 / 节税 / 税筹"，统一用"申报核对 / 汇算清缴代办"。

## 三、市场与目标客户

### 3.1 需求特征

- **个税是高频、强搜索、强焦虑的需求**，且有明确的季节性：**汇算季（次年 3 月 1 日 — 6 月 30 日）是全年流量峰值**。
- 我们的三个落地页正好覆盖峰值词（汇算清缴 / 月薪个税 / 年终奖个税），12 月—次年 1 月是年终奖与专项附加扣除确认季，也是流量波峰。

### 3.2 竞争格局与本方差异化

| 类型 | 代表 | 强项 | 弱点（我们的机会） |
|---|---|---|---|
| 官方工具 | 个人所得税 App | 权威、能真申报 | 只做申报，不做预算规划与倒算；体验重 |
| 代账 SaaS | 云账房 / 柠檬云 / 慧算账 | 功能全、面向会计 | **面向 B 端会计，不面向个人**；无 C 端获客入口 |
| 免费计算器网站 | 各类小站 | 有搜索流量 | **有流量无服务**，算完即走，无法变现 |

**我们的三张牌：**

1. **反向倒算 + 年终奖最优分配**（竞品普遍弱或没有）—— 直击"谈薪该报多少税前"的真实痛点，传播力极强
2. **隐私与离线**（数据不出浏览器、断网可算）—— 财务工具最敏感的就是信任
3. **背后有真实服务能力**（竞品缺的是交付，我们不缺）—— 工具是入口，服务才是产品

### 3.3 目标客户分层（按商业价值，不是按流量大小）

| 客群 | 典型场景 | 商业价值 | 我们的动作 |
|---|---|---|---|
| **个体户 / 个独 / 合伙（经营所得）** | 经营所得汇算、扣除项核对、申报 | ★★★ 高（代账 / 申报，可年费制） | 结果页**强引导** + 留资 |
| **需要年度汇算的纳税人** | 专项附加扣除是否填全、退税/补税 | ★★☆ 中高（汇算代办 / 咨询，单次） | 汇算页 + 留资 |
| **小微企业主** | 代账、申报、社保、用工成本 | ★★★ 高 | 预算表页 + 顾问 |
| 打工人（谈薪 / 月薪） | 到手倒推税前、年终奖怎么发 | ★☆☆ 低（与服务错配） | **只出分享图，不出服务引导** |

> **最后一行是硬约束，不是偏好**：谈薪人群是打工人，与企业财税服务需求错配，硬推只会伤害品牌。
> 但他们的传播力最强，所以策略是——**要他们的传播，不要他们的线索**。

## 四、商业模式与盈利模式（三层）

### 第一层：服务成交 —— 主营收（现在就能做，零依赖）

| 问题 | 答案 |
|---|---|
| 卖什么 | 代账 · 纳税申报 · 汇算清缴代办 · 税务咨询（**待定价，见第十章**） |
| 卖给谁 | 第二章 3.3 表中的 ★★★ / ★★☆ 客群 |
| 怎么卖 | 留资（省·市 + 场景 + 收入量级）→ 企业微信 → 顾问 1v1 → 签约 |
| 为什么是我们 | 交付由公司既有服务能力完成；工具本身不赚钱也不亏钱（服务器约 $3/月） |
| 关键指标 | 留资数 → 有效线索率 → 成交率 → 客单价 |

**为什么这一层是主营收**：工具侧的专业版订阅参考定价是 **9.9–19.9 元/年**，而一单代账/申报服务的客单价通常在千元量级 —— **1 个成交客户 ≈ 几百个订阅用户**。同样的运营精力投在服务转化上，回报差两个数量级。

**产品里已经为这一层埋好的钩子**：v1.17.0 起计算页不再让用户选"参保城市"，各地社保口径差异**故意留给留资后的顾问来核对** —— 这既是合规的降噪设计，也是自然的服务介入理由。

### 第二层：C 端专业版 —— 现金流补充（现在就能做，零依赖）

| 项 | 内容 |
|---|---|
| 权益（已收口为真实生效项） | 云端同步 / 多设备漫游 · 汇算清缴 PDF 完整报告 · 方案对比库 2→10 套 · 云端数据长期保留 |
| 铁律 | 计税能力永不锁定 |
| 收费方式（现在） | `ProCode` 兑换码：**线下收款 → 后台发码 → 用户自助兑换 → 权益即时生效**（完全绕开支付网关与备案依赖） |
| 收费方式（备案后） | 微信 / 支付宝官方支付（阶段16B） |
| 参考定价 | 9.9 – 19.9 元/年 |
| 战略价值 | 不只是收入 —— **付费用户 = 付费意愿已被验证的高质量线索**，顾问应优先跟进 |

### 第三层：B 端 API —— 第二增长曲线（备案 + 阶段15B 之后）

| 项 | 内容 |
|---|---|
| 卖什么 | 把我们已验证的计税能力做成对外 API，面向**代账公司 / 财务 SaaS / HR 系统** |
| 收费 | 按次 / 按年（待定价） |
| 前置条件 | ① ICP 备案通过；② 阶段15B 补齐**企业税种**（增值税 / 企业所得税 / 附加税费 / 印花税）—— 没有企业税种，B 端无货可卖 |
| 为什么值得等 | 这是唯一"收入不随人力线性增长"的一层（软件边际成本≈0） |

> ❌ **明确不做**：广告。财务工具的信任就是产品本身。

### 收入结构示意（不含 B 端 API）

```
第 1 年   服务成交为主（85%+） + 专业版订阅（<15%）
第 1–2 年 服务成交持续放大（SEO 复利 + 顾问复用）
第 2 年+  B 端 API 开始贡献，收入结构由"人力驱动"转向"资产驱动"
```

## 五、获客策略（三驾马车）

### 马车 A：SEO 落地页矩阵 —— 复利资产，长期主力 ⭐⭐⭐

**做法**：一税种一页（或一词一页），页面自带能跑的速算器 + 静态正文（爬虫不执行 JS 也能读到全部内容）+ `canonical` + 结构化数据。已被验证的模式，可低成本复制。

| 阶段 | 页面 | 状态 |
|---|---|---|
| 已完成 | 年终奖个税 / 月薪个税 / 汇算清缴 | ✅ 已上线 |
| 近期（3–5 天可交） | 社保基数 / 税后工资（参数库现成，纯复制既有做法） | ⏳ 待做 |
| 阶段15 起 | 劳务报酬 / 股权激励 / 离职补偿 / 增值税 / 企业所得税 / 印花税 … | ⏳ 待做 |

**关键判断**：SEO 是唯一"投入一次、持续收租"的渠道。
**但现有站点在境外，对国内搜索引擎收录不利** —— 这是"备案必须尽早启动"的最强理由：每拖一个月，就少一个月的收录积累。

### 马车 B：社媒冷启动 —— 即时流量，验证素材 ⭐⭐

5 套文案与发布节奏**已经写好**（即刻 / V2EX / 知乎 / 小红书 / 私聊种子用户），可直接执行：
第 1 天邀请种子用户 → 第 3 天修高优 bug → 第 5 天即刻 → 第 7 天 V2EX → 第 10 天知乎回答 → 小红书配截图跟进。

**执行红线**：谈薪 / 月薪类内容的目标是**传播 + PWA 安装**，不是线索；不要为了线索量去污染这类页面。

### 马车 C：私域与裂变 ⭐⭐

| 手段 | 状态 | 说明 |
|---|---|---|
| 结果分享图 + 二维码 | ✅ 已上线 | 每个用户都是分发节点，回流可归因（`?source=share`） |
| 企业微信活码 | ✅ **已配置（2026-09-16）** | 线索承接主通道：`https://work.weixin.qq.com/kfid/kfcdb871293d06fc4d0`，留资弹窗现场生成二维码且整块可点（扫码或点击都能进企微） |
| 邀请码（一机一码） | ✅ 已上线 | 初衷是防爬虫批量注册；但也是注册摩擦 —— **建议 2 周后按数据评估是否放开** |
| 老客户转介绍 | — | 成交后引导，成本最低的获客 |

| M4 备案通过并切境内 | 第 12 周末 | 境内域名可访问 + 官方支付开通 | 待定 |
| M5 B 端 API 首单 | 6 个月 | 15B 完成 + 外部客户签约 | 待定 |

### 7.2 三个角色（当前最关键的是分工，不是人数）

| 角色 | 职责 | 产能瓶颈 |
|---|---|---|
| **运营** | SEO 落地页内容、社媒发帖、数据观察 | 内容产出速度 |
| **顾问** | 线索跟进、报价、成交、复购 | **每顾问能承接的线索量**（真正的收入天花板） |
| **开发** | 阶段15/16、"获客弹药型"需求 | 只应做能带来关键词/线索/收款的需求 |

> **结论：收入瓶颈是"线索质量 × 顾问承接能力"，不是软件功能。** 因此阶段 0/1 的资源应优先给运营与顾问，而不是继续加功能。

## 八、财务假设（**当前为假设，需用前 30 天实测校准**）

### 8.1 成本

| 项 | 金额 | 说明 |
|---|---|---|
| 服务器（现状） | 约 $3/月（≈22 元） | 境外托管，承载账号与同步，计算不占带宽 |
| 域名 | 约 60–100 元/年 | `.com` 主域 + `.cn` 防御性注册 |
| 备案 | 0 元 | 非经营性备案免费 |
| 大陆轻量服务器（备案要求） | 约 60–100 元/月 | 备案需大陆资源；可先用最低配 |
| 人力 | 自有团队 | 运营 + 顾问 + 开发；**这是真实成本项，也是瓶颈** |
| **现金成本合计** | **< 150 元/月** | 产品模式的天然优势：计算不产生服务器成本 |

### 8.2 收入情景（**假设值，非预测**）

假设：留资率按访问量的 0.9% 计，有效线索 50%，成交率 15%（需实测替换）

| 情景 | 月访问 | 留资 | 有效线索 | 成交/月 | 客单价 | 月收入 |
|---|---|---|---|---|---|---|
| 保守 | 1,000 | 8 | 4 | ≈0.5 单 | 1,500 元 | ≈750 元 |
| 中性 | 3,000 | 27 | 13 | ≈2 单 | 2,000 元 | ≈4,000 元 |
| 乐观 | 10,000 | 90 | 45 | ≈7 单 | 2,500 元 | ≈17,500 元 |

专业版订阅（同期，量级小）：乐观情景约 100 位付费用户 × 15 元 ≈ 1,500 元/年 —— **定位是覆盖成本与筛选高质量用户，不是主营收入**。

### 8.3 敏感性（哪个变量最值钱）

| 变量 | 变化 | 对月收入的影响 |
|---|---|---|
| 成交率 15% → 8% | -47% | 收入近乎腰斩 |
| 客单价 2,000 → 3,500 元 | +75% | **最有效的杠杆：把单次咨询升级为年费代账** |
| 访问量 ×3（SEO 复利） | +200% | 长期最强，但需要时间积累 |

**给合伙人的结论**：短期提收入靠**客单价与成交率**（即顾问能力与报价结构），中长期靠**SEO 复利放大访问量**。
三者中，**访问量是唯一不能靠人力加速的变量** —— 这也是为什么备案（决定国内 SEO 效果）要现在启动。

## 九、风险与合规

| 风险 | 影响 | 对策 |
|---|---|---|
| **ICP 备案未启动**（最大风险） | 卡死官方支付 / 微信小程序 / 境内 SEO；排队 3–5 周不可压缩 | 本周买域名并提交备案；与阶段15 并行推进 |
| **换域名会丢用户本地历史** | PWA 的本地存储绑定域名 | **当前用户量为 0，是唯一零成本窗口** → 立即定死域名 |
| 谈薪流量与服务错配 | 硬推伤品牌、拉低线索质量 | 严格执行"工资/谈薪页不出服务引导"的硬约束 |
| 合规文案踩线 | 税务内容敏感 | 禁用"避税/节税/税筹"；统一"申报核对/汇算代办"；留资需显式同意并留痕 |
| 各地社保口径差异 | 用户误以为结果不准 | 计算页统一按全国口径提示；差异由顾问在留资后核对（省·市字段已落库） |
| 团队带宽被开发挤占 | 运营/开发/顾问三头烧 | 用第六章的筛子：只做能带关键词/线索/收款的需求 |
| 付费用户与线索未打通 | 浪费高质量信号 | 专业版用户应被视为高优线索，由顾问优先跟进 |

**主体与合规路线（已定，无需再论证）**：备案走**企业（单位）主体 · 有限责任公司**（个人备案不能收费、不能开微信支付、转企业须先注销再重备）。
付费初期包装为"服务/咨询费"性质，先做非经营性备案上线；待 B 端 API 明确经营性后再评估办证。
