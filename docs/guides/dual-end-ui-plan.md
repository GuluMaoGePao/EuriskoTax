## 1. 结论先说：推翻了的一个假设

早期判断是「手机 = 速算，桌面 = 完整测算」。**这个分流是错的**，被客群与商业目标否决：

| 客群 | 商业价值 | **主用端** | 服务引导 |
|---|---|---|---|
| 打工人（谈薪 / 月薪） | ★☆☆ | 手机 | ❌ 永不出（`BLOCKED_TYPES: ['reverse']`） |
| 个体户 / 小店（经营所得） | ★★★ | **手机** | ✅ 强引导 |
| 年度汇算纳税人 | ★★☆ | **手机** | ✅ `result_settlement` |
| 小微企业主 / 财务 HR | ★★★ / 第二曲线 | **电脑** | ✅ 顾问 + API |

商业价值最高的两类偏偏主用手机。把重任务赶到桌面 = 把最值钱的线索客群推到他们不用的端，
`calc_done` 直接掉，北极星 `lead_submit / calc_done` 跟着掉。

**修正后的双端定位：**

| | 手机 | 桌面 |
|---|---|---|
| 角色 | **主战场**（多数流量 + 高价值线索） | 高客单 + 信任 + B 端 |
| 要什么 | 不只"算得快"，**必须"能算完"** | 信息密度、可信度、可交付（导出 / 打印） |
| 怎么优化 | **降低重任务的输入成本** | 提升单位屏信息与决策依据 |

## 2. 竞品对标（补 IA 维度）

项目既有竞品表（见阶段15 方案 §4）是**能力维度**，缺少信息架构维度。补充后：

| 产品 | 手机端 IA | 桌面端 IA | 取 / 弃 |
|---|---|---|---|
| 个人所得税 App | 底部 Tab + 首页宫格 + 场景入口 | 无 | ✅ 取「宫格 + 场景」；❌ 弃「重流程 + 强制登录」 |
| 云账房 / 慧算账 / 柠檬云 | 弱 | 左侧树状导航 + 工作区 | ✅ 取「桌面工作区感」；❌ 弃「面向会计的层级」 |
| 个税计算器小站 | 单页无导航 | 单页 | ✅ 取「一屏算完」；❌ 弃「算完即走」 |
| 记账 / 金融 App | 底部 Tab + FAB 承载唯一主行动 | — | ✅ 取「FAB = 唯一主行动」 |
| Notion / 飞书 / Linear | 底部 3–4 Tab | 左侧栏（层级深） | ✅ 取「浅层级用顶部 Tab，不浪费左侧栏」 |

### 最关键的一条

> **没有任何一家竞品做过「桌面办公 + 手机速算」的任务分流——因为它们的双端本就是不同产品。**
> 我们是唯一「一套产品跨两端」的。**单端惯例可抄，双端策略无可抄对象。**

因此本方案只采用已被验证的**单端惯例**，不在双端策略上创新（0 用户，无数据做 A/B）。

## 3. 设计基线

### 3.1 两条解耦的断点

| 维度 | 断点 | 说明 |
|---|---|---|
| **导航形态** | **768px** | 手机底部 Tab 栏 ⇄ 桌面顶栏下方 Tab 行 |
| **内容形态** | **1024px** | 单列 ⇄ 多列网格 / 宽容器 |

### 3.2 屏幕预算（目标）

| 页类型 | 固定层 | 目标占比 |
|---|---|---|
| 顶层页（手机，含底栏） | 顶栏 56 + 底栏 52 + 安全区 34 | **≤16%** |
| 任务页（计算中） | 顶栏 56 + 紧凑顶栏 + 预览条 | **≤18%**（原 26%） |

**任务页实测（S3 后）**：56（全局顶栏）+ 约 72（紧凑顶栏，S3 前约 99）+ 约 46（预览条）≈ **174px，约 22%**。
离 18% 目标还差约 34px，缺口几乎全部来自未动的全局顶栏 56px —— 见文末「剩余决策项」。

### 3.3 容器

| Token | 值 | 用途 |
|---|---|---|
| `--c-narrow` | 720px | 速算器 / 表单（行长 65–75 字符最优） |
| `--c-default` | 1024px | 首页 / 列表 / 网格 |
| `--c-prose` | 760px | SEO 正文阅读 |

> 工具页原为 `max-w-3xl`（768px），桌面下 20 个工具挤在 768px——这是桌面端最明显的浪费。

### 3.4 无障碍底线

| 项 | 处理 |
|---|---|
| 未激活 Tab 色 | `#9ca3af`（对比度约 2.6:1，不达 WCAG AA）→ `#6b7280`（约 4.8:1）**已完成** |
| 退税 / 补税 | **禁止只靠红绿区分**，必须同时有「应退 / 应补」文字（约 8% 男性红绿色觉障碍） |
| 减少动效偏好 | `prefers-reduced-motion` 已加入令牌层 |
| 输入框字号 | 强制 16px，防 iOS 聚焦缩放 |

## 4. 商业硬约束（改版不许越过）

| # | 约束 | 落地要求 |
|---|---|---|
| 1 | 北极星 `lead_submit / calc_done` | 改版唯一验收标准 = 北极星不降 |
| 2 | 谈薪页永不出引导（门禁断言） | 引导位必须**按计算类型动态决定**，不许做成到处挂的固定组件 |
| 3 | 「服务介入理由」是设计出来的 | **参保城市不许补回计算页**，差异留给留资后的顾问核对 |
| 4 | 措辞红线 | 禁「避税 / 节税 / 税筹」，统一「申报核对 / 汇算清缴代办」 |
| 5 | 开发资源筛子：能带来关键词 / 线索 / 解锁收款吗 | 不能 → 排队 |

### 按筛子砍掉的项

| 原提议 | 处置 | 理由 |
|---|---|---|
| 计算页桌面双栏（左表单右结果） | ❌ 砍 | 不带关键词 / 线索 / 收款；覆盖 4 个流程页，风险最高 |
| Excel 粘贴导入 | ❌ 砍 | 同上；等 B 端 API 启动后才是真需求 |
| 键盘快捷键 | ⬇️ 降级 | 顺手做，不单独立项 |

> 桌面办公诉求改由**低成本项**承接：工具页加宽、助手 push 侧栏、导出打印样式。

- **`src/css/tokens.css`（新增）**：字体 / 字号 / 语义色 / 间距 / 圆角 / z 层级 / 动效 / 容器 + `.dark` 镜像 + `prefers-reduced-motion`。含 `--plan-*` 与 `--pay-*` 令牌，**为后续支付预留但当前无 UI 消费**。

- **`src/css/toolbox.css`**：底栏与桌面 Tab 行全部改取令牌；底栏触摸区达 44px；桌面形态彻底收起底栏；新增 `:focus-visible`。

- **测试**：新增 5 例钉住契约（两端同步、助手不占导航位、`updateTabBar` 与 `syncNav` 等价、

  而不是跟着视口宽度走**：视口变宽和侧栏推开是同一结果的两种原因，按视口写死会漏掉后者。
- **S6 助手桌面推开**：侧栏宽度收进令牌 `--assistant-w`（抽屉宽度与让出的内容宽度必须同源）；
  ≥1280px 时 `#app-container` 让出同宽实现推开，低于此宽仍为覆盖 + 遮罩（480 + `--c-narrow` 720 = 1200，
  向上取标准断点 1280）。JS 只在开关时切 `body.assistant-open`，**形态判断完全交给媒体查询**。
- **测试（助手推开）**：新增 3 例钉住这个唯一开关（打开打上 / 三条关闭路径都摘掉 / toggle 不残留）——
  漏摘一次，内容区就永久留白一整个侧栏的宽度。
- **S7 落地页接入令牌**：21 个页面先加载 `src/css/tokens.css`，`landing.css` 的共享语义色改为
  `var(--c-*)` 映射。迁移时**往令牌层补了 5 个档位**（`--c-success-text` / `--c-warning-text` /
  `--c-warning-bg` / `--c-warning-line` / `--c-brand-line`）—— 原 `--c-success` / `--c-warning`
  是徽章底色用的饱和色，当文字色只有约 2.5:1，直接映射会把落地页正文的对比度打穿。
  品牌投影走 `--c-brand-rgb` 三元组，品牌色仍只有一处定义。
- **测试（落地页令牌）**：新增 4 例（每页都加载 tokens.css / 共享色映射到 `var(--c-*)` /
  引用的变量都有声明 / 零内联样式）。**第一条最关键**：21 个页面里漏掉一个，那一页就是裸色，
  而 `landing.css` 自己看不出来 —— 只能从页面侧钉。
- **有意不做**：字号 / 圆角 / 间距不迁（H1 30px、卡片圆角 14px 在令牌阶梯里没有对应档，
  硬套等于改渲染），落地页独有的「一次性色」留在 `landing.css` 一段内并注明理由。
- **S8 打印样式**：新增 `src/css/print.css`（只有 `@page` + `@media print` 两块）。
  屏幕外壳（导航 / Tab 栏 / 悬浮球 / 助手抽屉 / 横幅 / 按钮）不进纸面；`max-height` 与 `overflow`
  折叠的内容在纸面摊开；`thead` 每页重复表头；结果行不跨页断开。
  - **深色模式在 JS 侧处理**：浏览器默认不打印背景色，深色模式的浅色文字会印成「白纸上的白字」；
    Tailwind `dark:` 变体是 `.dark 后代`选择器，CSS 侧无法整体失效 —— 改为 `beforeprint` 摘类、
    `afterprint` 还原。覆盖规则带 `!important` 是因为 Tailwind CDN 的 `<style>` 注入位置不可控。
- **S8 分享图**：静态确认未受影响 —— `buildHtml` / `rowHtml` / `qrBlockHtml` 全部内联样式不挂 class，
  `toolbox.css` / `tokens.css` 无裸元素选择器（分享图容器挂在真实 `body` 上，元素选择器会渗进图里）。
  两条都已固化成断言。**像素层面仍需人工对比一次**（项目缺视觉回归）。

### 为什么不把 Tailwind config 变量化

全站大量使用透明度修饰符（`bg-primary/90`、`ring-primary/50`）。变量化后若 CDN 不支持
`<alpha-value>`，这些会**静默失效**；当前无法做视觉回归，风险高于收益。
因此 Tailwind config 保留 hex 副本并与令牌**同值镜像**（改色需同步两处），
全量变量化留到具备视觉回归条件时进行——届时改色只需改 `tokens.css` 一处。

## 8. 剩余决策项（本次没做的那个 56px）

手机上把计算页固定占比从 22% 压到 18% 以内，差的 34px 几乎全在**全局顶栏（56px）**上。
唯一能拿到它的做法是在计算页（手机）隐藏全局顶栏，只留计算页自带的紧凑顶栏（含返回按钮）。

| | 说法 |
|---|---|
| 收益 | 再省 56px，手机上约回落至 13%；专注式任务流是成熟惯例（外卖 / 结账类 App 普遍如此） |
| 代价 | 顶栏上有登录入口、用户菜单、主题开关、PWA 安装；深链直达计算页的用户在表单中部会失去这些入口 |
| 为什么这次没做 | 当前**无法做视觉回归**，为一个锦上添花的像素目标冒功能回退风险不划算 |
| 何时做 | 具备视觉回归（截图对比）之后，或先补一条「计算页必须可返回」的端到端断言再动 |

在此之前不动它 —— 收益是锦上添花，回退动的是登录路径，性价比不对等。
