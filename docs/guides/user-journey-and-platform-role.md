## 零、一句话定位

EuriskoTax 是**先给数、再给口径、必要时把人交给顾问**的税费计算器。

它不代账、不代办、不筹划，也不替任何人做决定；它把一笔税算清楚，并说明**这笔数是怎么来的、
依据哪一条口径**，然后把需要人工判断的部分交给财税顾问去谈。

这条定位不是修辞，它同时决定了三件事：工具永远不锁（`stage19-ui-redesign-plan.md:71`
「计税能力永不锁」）、结果必须带免责（`copy-standard.js:21` 主句固定不可改字）、
站内不能出现任何购买语义（`copy-standard.js:116` + `tests/filing-compliance.test.js` 断言「无在线支付入口」）。

## 一、谁在用：两条正交的 persona 轴

### 1.1 常态 persona（你是谁）

真源 `src/js/data/tool-registry.js:6346-6380` 的 `SCENARIOS`，六张身份卡：**只影响推荐排序，不影响工具可达性**（`src/js/ui/identity-pref.js:5-15` 三条边界）。

| id | 人群 | 一句话 | 代表工具 |
|---|---|---|---|
| `employee` | 上班族 | 领工资、算年终奖、看汇算退税 | salary-tax / bonus-tax / annual-settlement / special-deduction / net-salary |
| `freelance` | 自由职业 / 兼职 | 劳务报酬预扣、自己缴社保 | withholding / business-income / social-base / private-pension |
| `owner` | 个体户 / 小店 | 经营所得、开票缴税、核定还是查账 | business-income / vat / surtax-stamp / disability-fund |
| `finance` | 企业财务 / 会计 | 企税、增值税、附加与印花 | corporate-income-tax / vat / surtax-stamp / disability-fund |
| `executive` | 高管 / 股东 / 临近退休 | 股权激励、离职补偿、退休与年金 | equity / severance / early-retirement / annuity / expat |
| `hr` | HR / 薪酬 | 发工资、算用工成本、社保与残保金 | employer-cost / social-base / disability-fund / severance |

### 1.2 事件 persona（你这回遇上了什么事）

出处 `docs/development/stage19-ui-redesign-plan.md:315-322`：卖房、拿期权、被裁、生孩子、第一次工作……

**这两条轴正交**：任何人都会在某个瞬间变成「卖房的人」「被裁的人」，而身份不一定说得清自己属于哪一类。
产品上的结论写在 `stage19-ui-redesign-plan.md:520`——**首屏 CTA 最终落到事件轴而非身份三选**：
「身份不是人人都说得清，但每个人都认得自己遇到了什么事」。

这条结论对工具页有直接约束力（见 §6）。

## 二、每条路径：入口 → 想算什么 → 怎么算 → 得到什么 → 然后呢

北极星是 `calc_done / lead_submit`（分母不是 visit，`stage19-ui-redesign-plan.md:72`）——
**免登录、零门禁地把数算出来**是这条链路的前提，任何在这之前挡一道的东西都是在砍自己的分母。

### 2.1 打工人（employee）

| 环节 | 内容 |
|---|---|
| 怎么进来 | 「年终奖个税怎么算」「月薪 2 万到手多少」→ 20 个 SEO 落地页之一；或朋友发来的分享图 |
| 想算什么 | 这笔钱到手多少 / 年终奖单独计税还是并入综合 / 今年汇算能退多少 |
| 怎么算 | 落地页或工具页点开 → 一屏填 3~5 个框（薪资 / 社保基数 / 专项附加）→ 即时出数（算的过程在本机，不上云） |
| 得到什么 | 主结果（到手 / 应退应补）+ 易错口径 + 政策依据文号 + 结果页「下一步」 |
| 然后呢 | **到此为止**。反向倒算（`reverse`）在留资黑名单里（`lead-touchpoints.js:18-31`），打工人群整体判定为 ★☆☆ —— 「要他们的传播，不要他们的线索」（`business-plan-for-partners.md:126-127`，定性为硬约束不是偏好） |

### 2.2 自由职业 / 兼职（freelance）

| 环节 | 内容 |
|---|---|
| 怎么进来 | 「劳务报酬个税」「经营所得vs劳务报酬」→ 落地页；或常年从工具页进 |
| 想算什么 | 这笔劳务被预扣了多少、明年汇算能不能退回来、自己缴社保划不划算 |
| 怎么算 | 劳务报酬速算（一次一算）→ 年度iscal 汇算预测（跨笔汇总，需多步） |
| 得到什么 | 预扣 vs 汇算差额 —— 这才是他要的答案（「这一步通常能退回来多少」） |
| 然后呢 | 允许留资（`forward` / `comprehensive` 在白名单内），但**信任句不带时效**（`copy-standard.js:73`） |

### 2.3 个体户 / 小店老板（owner）

| 环节 | 内容 |
|---|---|
| 怎么进来 | 「个体工商户怎么交税」「核定征收 vs 查账征收」→ 落地页 |
| 想算什么 | 今年要交多少（经营所得 + 增值税 + 附加与印花）、核定划算还是查账划算、要不要请会计 |
| 怎么算 | 速算器给数；真要做决定得上完整测算（21 个之一，`business-income` 的预算表形态） |
| 得到什么 | 一个能拿去跟会计/家人对账的数 + 口径解释 |
| 然后呢 | **★☆☆ 之外的第一优先级线索**（`business-plan-for-partners.md:119-145` 评 ★★★）：服务转介客单价 1,500–2,500 元 |

### 2.4 企业财务 / 会计（finance）

| 环节 | 内容 |
|---|---|
| 怎么进来 | 「残保金怎么算」「增值税小规模减免」→ 落地页；**高复用，常 bookmark** |
| 想算什么 | 这个月要报多少、政策变了没有、口径跟去年对不对得上 |
| 怎么算 | 多为一次性速算；会反复用（工具点是固定几个） |
| 得到什么 | 数 + 政策依据（他要拿这一句去跟老板/税局对） |
| 然后呢 | ★★★；同时也是**内容更新公告**的重度读者（`content-center-ui.js` 三个展示位） |

### 2.5 高管 / 股东 / 临近退休（executive）

单次、低频、金额大：股权激励行权、离职补偿（N+1 怎么免税）、提前退休、年金。
这类题目**参数多、口径绕**，正是 21 个完整测算存在的理由。

### 2.6 HR / 薪酬（hr）

发工资前算一遍用工成本、社保与残保金、批量算一批人（免费 5 行/次，超限拒绝整批——
`src/js/ui/batch-ui.js:26`，「宁可一行都不算」是不给半份答案）。

### 2.7 路径的共同结构

```
进来（SEO / 分享 / 常访） → 找到工具（≤2 跳） → 填 3~5 个框 → 出数 + 口径 + 依据
   → 分支 A：拿走（分享图 / 报告）→ 传播 → 下一个进来
   → 分支 B：这数我拿不准 / 想省事 → 留资 → 顾问 → 站外成交 → 发码 → 回站开通
```

**分支 A 是本体的价值（传播的引擎），分支 B 是收入。** 两者共用同一个 `calc_done` 前提。

## 三、平台扮演什么角色

| 角色 | 是 | 不是 |
|---|---|---|
| 计算器 | 把一笔税算出来 | 不做税务筹划，不替人选方案 |
| 口径解释器 | 说明这笔数依据哪一条、哪些参数最容易填错 | 不做权威认定（不得出现「权威/官方认证」等词，`copy-standard.js:113`） |
| 顾问撮合 | 传递用户**主动提交**的联系方式与本次情境 | **不对咨询结论负责**（`agreement.html:134-137`），不代办、不代理申报、不代理记账 |
| 数据保管者 | 计税输入留在本机；记录镜像云端供换设备（**仅登录用户，且必须显式披露**） | 不采集收入/扣除额等计税输入明细（`privacy.html:117-123`） |

关于第三行有一条必须照原样说的边界（`user-facing-copy-standard.md:494-497`）：

> 对外承诺只能落在**咨询解答**。一旦文案出现「代办 / 代理申报 / 代理记账 / 包过 / 包退税」，
> 就跨到《涉税专业服务监管办法》约束的涉税专业服务（需实名制报送、不得虚假宣传、不得承诺结果），
> 代理记账另需财政部门许可 —— **主体经营范围是「商务咨询服务」，未必覆盖**。

关于第四行有一条容易被自己人写成假话的地方（`index.html:1672-1675` 的注释记着这段历史）：

> 站内写的是「全部计算在您的浏览器本机完成，不上传任何数据」，但**这句对登录用户是半真的** ——
> 登录后的测算**记录**会镜像到云端，只有计税**输入**始终只留在本机。
> 因此正式表述必须带上后半个从句，写一半就是虚假宣传。

## 四、怎么获利：三层，第一层是唯一的主力

### 4.1 第一层（主营收）：财税服务转介

`business-plan-for-partners.md:119-145`：客群分级 ★★★ 个体户/个独/合伙、★★☆ 需年度汇算的纳税人、
★★★ 小微企业主、★☆☆ 打工人（**只出分享图，不出服务引导**）。
客单价 1,500–2,500 元，一句关键的量化判断在同文档 L143：

> **1 个成交客户 ≈ 几百个订阅用户。**

同文档 L269-275 还有一条反直觉的结论：**收入瓶颈是线索质量 × 顾问承接能力，不是软件功能**。

### 4.2 第二层：专业版 ProCode——名额分配给「已被验证意愿」的人

参考定价 9.9–19.9 元/年（`business-plan-for-partners.md:152-156`，**仅商业文档，站内不出现**）。
定位写得明白：**覆盖成本与筛选高质量用户，不是主营收入**（乐观情景约 100 人 × 15 元 ≈ 1,500 元/年）。

收款形态是刻意绕开的（`plan.js:58-63`、`user-facing-copy-standard.md:19-33`）：

```
线下/站外收款 → 运营后台发码 → 用户回站自助兑换 → 权益即时生效
```

对三类能锁的能力（`copy-standard.js:106` 是唯一书面出处）：
方案对比库 2→10（`scenario-store.js:19-20`）、批量 ≤5 行（`batch-ui.js:26`）、汇算清缴 PDF 完整报告（`final-report.js:360`）、云同步。

> ⚠️ 待核对：`copy-standard.js:95` 的升级码输入框占位写的是 `EUR-XXXX-XXXX`，而后端实际前缀是 `PRO`
> （`proCodeService.js:8`）；`EUR-` 对应的是**注册邀请码**。疑似遗留笔误，改前先确认。

### 4.3 第三层（待解锁）：B 端 API

硬前置 ICP 备案 + 阶段 15B 企业税种（`business-plan-for-partners.md:158-165`），未开工。

### 4.4 为什么站内不允许出现购买/价格/订阅

不是洁癖，是牌照问题（下节 5.2）：**经营性互联网信息服务需要 ICP 经营许可证，不只是备案号。**
现阶段把交易放在站外完成，正是为了让「已经有数据收入的这部分」不依赖那张许可证。

## 五、备案与合规：现状、待办与四条硬门槛

### 5.1 现状与唯一待办

真源 `src/js/ui/site-filing-ui.js:42-60`，改一处全站（22 页）生效：

| 项 | 值 | 状态 |

两件容易说错的事：

1. **不要说「全站每页都有备案页尾」** —— 主应用常驻页尾已在 v1.124.0 删掉（`index.html:2887-2896`）。
   现在的落点只有三处：**登录页页尾**（工信部口径的首页底部即此处）、**我的 → 关于我们弹窗**、**21 个落地页页脚**。
2. **不要猜测地写假号** —— 未备案展示备案号是违规不是文案瑕疵（`site-filing-ui.js:33-37`），
   `tests/site-filing.test.js` 会拦形似假号的字符串。

### 5.2 硬门槛一：经营性 ICP 许可证（决定什么时候能开在线支付）

`user-facing-copy-standard.md:488-493`：

> 非经营性备案**不等于**可以开展经营性互联网信息服务。未取得许可证即开展收费，
> 落在《互联网信息服务管理办法》第十九条（可责令关闭、罚款）。
> 阶段 16B「官方支付」的硬前置是**许可证**，不只是备案号。

这解释了 4.2 的形态为什么必须存在，也解释了 `plan.js:62` 那句「站内零购买语义」。

### 5.3 硬门槛二：不在主体的经营范围里

主体经营范围是**商务咨询服务**。代理记账需财政部门许可，不在其中（§3 表格第三行已引）。
因此产品上有一条对应的自律：留资白名单**不**按 21 个税种铺满，只留接得住的 4 类
（`lead-touchpoints.js:18-31`，三条依据：《广告法》第 28 条、《涉税专业服务监管办法》、《个保法》第 6 条最小必要）。

### 5.4 硬门槛三：广告法与「不写时效」

`copy-standard.js:113-119` 黑名单三档：

- **absolute**：有问必答 / 包过 / 权威 / 官方认证 / 100% 准确 / **永久授权**（已改「长期有效」）
- **paid**：免费领取 / 立即购买 / 了解专业版 / 基础版 vs 专业版 / 订阅套餐 / 开通套餐
- **sla**：1 个工作日内 / 24 小时内 —— 做不到就不写，站内统一「顾问会尽快与您联系」

### 5.5 硬门槛四：免责必须随结果出现

主句固定不可改字（`copy-standard.js:21`）：**「本测算结果仅供参考，不构成税务建议；」**
结果区 / 分享图 / 导出报告 / 落地页页脚四处都要带，法律正文在 `agreement.html:141`。

## 六、这份梳理反过来规定了产品长什么样

| 约束 | 来源 | 对页面的规定 |
|---|---|---|
| 免登录、零门禁算完 | 北极星 `calc_done` | 找工具的路径要短（≤2 跳），任何前置提问都是砍分母 |
| 入口永不被筛选掉 | `identity-pref.js:5-15`、§3.9 | 身份 / 分类切换只能是**视图**，总数永远可.count 出来，且会话级不落存储 |
| 出口只在接得住的 4 类 | `lead-touchpoints.js:18-31` | 服务引导不能跟着分类泛化 |
| 事件轴优先于身份轴 | `stage19-ui-redesign-plan.md:520` | 分类要是「人遇上的事」，不是「我们的内部实现」 |
| 站内零购买语义 | §4.4 / §5.2 | 页面上不存在价格与购买，升级入口只承接已拿到码的人 |
| 免责随结果 | §5.5 | 每个算出数的页面都要能一眼看到那一句 |

**工具页据此要解决的问题**（下一轮改造的输入）：现在的工具页把「5 个速算分组」纵向摊成一摞、
上面又有一条内容几乎相同的锚点条，等于**同一套分类讲了三遍**（组头一行、锚点一行、类型筛选一行），
而人真正要的东西（我这件事该用哪个工具）藏在这三套导航底下。
改造的方向是：把分类收成**一行选择器**，让内容区一次只呈现一类，并把该场景下的
速算与完整测算放进同一屏 —— 这既消掉了重复导航，也让「要快还是要全」变成一个当场能做的选择。
