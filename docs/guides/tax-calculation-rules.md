## 1. 综合所得计税规则

### 1.1 收入范围及计算方式

| 所得类型 | 收入额计算方式 | 政策依据 |
|---------|--------------|---------|
| 工资薪金所得 | 全部税前收入 | 《个人所得税法》第六条 |
| 劳务报酬所得 | 收入 × (1 - 20%) | 《个人所得税法实施条例》第十四条 |
| 稿酬所得 | 收入 × (1 - 20%) × 70% | 《个人所得税法实施条例》第十四条 |
| 特许权使用费所得 | 收入 × (1 - 20%) | 《个人所得税法实施条例》第十四条 |

**综合所得收入额合计公式**：
```
综合所得收入额 = 工资薪金 + 劳务报酬×80% + 稿酬×80%×70% + 特许权使用费×80%
```

> **术语区分（勿混用）**：
> - **收入额**：税法口径，劳务报酬/稿酬/特许权使用费已按 80%／80%×70% 折算，是计算应纳税所得额的基数
> - **税前收入**：界面口径，指未扣任何费用的收入合计 = 工资薪金 + 劳务报酬 + 稿酬 + 特许权使用费 + 年终奖，即结果区「税前年收入」与预算表汇总行「税前收入」（取值 `incomeDetails.preTaxTotal`）
>
> 因此预算表汇总行不显示「收入额」，应纳税所得额直接取税务引擎的 `taxDetails.taxableIncome`。

### 1.4 计算公式

**应纳税所得额**:
```
年度应纳税所得额 = 综合所得收入额
                  - 60,000元（基本减除费用）
                  - 专项扣除（三险一金）
                  - 专项附加扣除
                  - 其他扣除
                  - 符合条件的公益慈善捐赠
```

**应纳税额**:
```
年度应纳税额 = 年度应纳税所得额 × 适用税率 - 速算扣除数
```

## 2. 经营所得计税规则

### 2.1 收入范围

| 所得类型 | 说明 |
|---------|------|
| 个体工商户生产经营所得 | 个体工商户从事生产、经营活动取得的所得 |
| 个人独资企业投资者所得 | 个人独资企业投资者的生产经营所得 |
| 合伙企业投资者所得 | 合伙企业个人合伙人的生产经营所得 |
| 个人从事其他生产经营活动所得 | 如个人从事办学、医疗、咨询等活动 |

### 2.2 扣除项目

| 扣除类型 | 标准 | 政策依据 |
|---------|------|---------|
| 投资者减除费用 | 5,000元/月 × 工作月数（无综合所得时） | 《个人所得税法实施条例》第十五条 |
| 成本费用 | 实际发生的成本、费用、税金等 | 《个人所得税法》第六条 |
| 以前年度亏损 | 可结转5年弥补 | 《个人所得税法》第十八条 |
| 专项附加扣除 | 仅无综合所得时可扣除 | 《个人所得税法实施条例》第十五条 |
| 专项扣除（社保/公积金） | 个人缴纳部分（仅无综合所得时可扣除） | 《个人所得税法实施条例》第十五条 |

### 2.2.1 工作月数说明

**年工作总月数**：一年中实际工作的月数，不满12个月时需要调整计算。

| 场景 | 工作月数 | 投资者减除费用 |
|------|---------|--------------|
| 全年工作 | 12 | 60,000元/年 |
| 半年工作 | 6 | 30,000元/年 |
| 一个月 | 1 | 5,000元/年 |

**专项扣除计算**：社保/公积金月度金额 × 工作月数 = 年度金额

### 2.3 税率表（经营所得适用）

| 级数 | 全年应纳税所得额 | 税率 | 速算扣除数 |
|:---:|-----------------|:---:|-----------:|
| 1 | ≤30,000 | 5% | 0 |
| 2 | 30,000-90,000 | 10% | 1,500 |
| 3 | 90,000-300,000 | 20% | 10,500 |
| 4 | 300,000-500,000 | 30% | 40,500 |
| 5 | &gt;500,000 | 35% | 65,500 |

**政策依据**: 《个人所得税法》第三条

### 2.4 减半征收优惠（2023-2027年）

- **适用对象**: 年应纳税所得额≤2,000,000元的部分
- **优惠内容**: 减按50%计入应纳税所得额
- **政策依据**: 财政部公告2023年第6号

**计算公式**:
```
减免税额 = min(应纳税所得额, 2,000,000) × 适用税率 × 50%
实际应纳税额 = 应纳税额 - 减免税额
```

### 2.5 计算公式

**应纳税所得额**:
```
应纳税所得额 = 收入总额 - 成本 - 费用 - 税金 - 损失 - 其他支出 - 允许弥补的以前年度亏损
```

**应纳税额（未减半）**:
```
应纳税额 = 应纳税所得额 × 适用税率 - 速算扣除数
```

**代码实现**: `src/js/calculation/tax-calculator.js` 第1008-1110行 `calculateBusinessTax()` 函数

## 3. 分类所得计税规则

### 3.1 收入范围及税率

| 所得类型 | 税率 | 政策依据 |
|---------|:---:|---------|
| 利息、股息、红利所得 | 20% | 《个人所得税法》第三条 |
| 财产租赁所得 | 20% | 《个人所得税法》第三条 |
| 财产转让所得 | 20% | 《个人所得税法》第三条 |
| 偶然所得 | 20% | 《个人所得税法》第三条 |

### 3.2 特殊规定

| 项目 | 规定 | 政策依据 |
|-----|------|---------|
| 彩票中奖 | 单次中奖收入≤10,000元免征 | 财税字〔1998〕12号 |
| 发票中奖 | 单张发票奖金≤800元免征 | 财税字〔1998〕12号 |
| 股票转让所得 | 暂免征收 | 财税字〔1998〕61号 |

### 3.3 计算公式

**利息、股息、红利所得**:
```
应纳税额 = 每次收入额 × 20%
```

**财产转让所得**:
```
应纳税所得额 = 转让财产收入额 - 财产原值 - 合理费用
应纳税额 = 应纳税所得额 × 20%
```

## 4. 反向倒算规则

### 4.1 全部模式与单个模式

**全部模式**: 同时计算并展示三种计算模式（保守、均衡、进取）的结果，上方对比表格，下方三种模式详细预算表

**单个模式**: 仅计算并展示所选单一模式的结果

### 4.2 计算模式定义

| 模式 | 计算基准 | 说明 |
|------|---------|------|
| 🌱 保守模式 | 档位下限+1 | 最低门槛，稳健规划 |
| ⚖️ 均衡模式 | 档位中间值 | 常规预算，平均水平 |
| 🚀 进取模式 | 档位上限 | 积极规划，接近上限 |

### 4.3 按目标税率倒算

**核心算法**:
1. 根据目标税率确定对应的应纳税所得额范围 [min, max]
2. 根据计算模式确定应纳税所得额基准值
3. 税前收入 = 应纳税所得额 + 扣除总额
4. 计算税额和税后收入

**边界处理**:
- 最低档位（min=0）: 设置合理基准1元/年，符合应纳税所得额1-36000元适用3%税率
- 最高档位（无上限）: 使用固定增量（均衡+10万，进取+20万）

**代码实现**: `src/js/calculation/tax-calculator.js` 第785-865行 `calculateFromTargetRate()` 函数

### 4.4 按月度税后收入倒算

**核心算法**:
1. 年度税后收入目标 = 月度税后收入 × 工作月数
2. 使用二分法精确搜索税前收入
3. 迭代公式: `税前收入 = 税后收入 + 应纳税额`

**计算精度**: 二分法，精度达0.01元

**代码实现**: `src/js/calculation/tax-calculator.js` 第867-939行 `calculateFromMonthlyNet()` 函数

### 4.5 按目标税额倒算

**核心算法**:
1. 已知税额，反推应纳税所得额
2. 税前收入 = 应纳税所得额 + 扣除总额

**代码实现**: `src/js/calculation/tax-calculator.js` 第941-1017行 `calculateFromTargetTax()` 函数

### 4.6 最高档位计算规则

当应纳税所得额超过最高档位下限，且无上限时：

| 模式 | 计算规则 |
|------|---------|
| 保守模式 | `min + 1` 或 `minimumTaxableIncome` |
| 均衡模式 | 直接使用二分法算出的基准值 `baseTaxableIncome` |
| 进取模式 | `Math.max(baseTaxableIncome, min + 20万/10万)` |

### 4.7 年终奖税额处理

**重要说明**:
- 年终奖为0时，年终奖税额必须为0
- 综合所得和经营所得的反向倒算统一处理年终奖税额
- `bonusTax` 变量在函数开头初始化为0，确保所有代码路径都能访问
- 经营所得不涉及年终奖，始终使用0作为年终奖税额

**代码实现**: `src/js/calculation/tax-calculator.js` 第1278行初始化，第1318行计算，第1357行保存

## 5. 税收优惠与特殊规则

### 5.1 公益慈善捐赠

**规则**:
- 捐赠额未超过应纳税所得额30%的部分可扣除
- 国务院规定全额扣除的，从其规定

**计算公式**:
```
可扣除捐赠额 = min(实际捐赠额, 应纳税所得额 × 30%)
```

**注意**: 慈善捐赠是年度一次性扣除，不应在月度预缴中分摊

**政策依据**: 《个人所得税法》第六条

### 5.2 年终奖计税选择

**规则**:
- **单独计税**: 年终奖 ÷ 12确定税率，税额 = 年终奖 × 税率 - 速算扣除数
- **合并计税**: 与工资薪金合并，按综合所得税率计算

**政策依据**: 财政部公告2023年第28号

**代码实现**: `src/js/calculation/tax-calculator.js` 第187-197行 `calculateBonusTax()` 函数

### 5.3 临界点提醒

当应纳税所得额接近税率跳档临界点时自动提醒，帮助用户优化收入结构

**代码实现**: `src/js/calculation/tax-calculator.js` 第45-64行 `checkTaxBracketThreshold()` 函数

### 5.4 年终奖最优分配

自动计算工资与年终奖的最优分配比例，基于税率表临界点直接计算，O(1)复杂度

**代码实现**: `src/js/calculation/tax-calculator.js` 第66-119行 `calculateOptimalBonusAllocation()` 函数

## 8. 社保缴费基数规则

### 8.1 最低基数标准（分层口径）

**为什么需要分层**：各城市缴费基数下限差异极大（同一年度可相差一倍以上）。全站统一用全国平均 7546，会让**高基数城市**的用户被误告「基数合规」、**低基数城市**的用户被误报「低于最低标准」—— 两类都是给用户错误结论。

> **2026-09 取舍（v1.17.0）**：按城市分档校验的**端上部分已回退**。计算页不再让用户选「参保城市」，统一按**全国口径**提示 —— 原因是各地口径差异大，用户多数并不确定该选哪个，多一步选择反而容易给出误导性结论；城市改由留资/咨询时收集，**由顾问核对当地口径后再给结论**。城市参数库与公开端点仍保留（见 §8.4），供后续「社保基数」SEO 落地页复用。

**生效顺序**（后者覆盖前者，最终以最后一个为准）：

| 层级 | 来源 | 说明 |
|:---:|------|------|
| ① | `src/js/calculation/tax-constants.js` | 全国平均兜底出厂值（`7546`） |
| ② | `tax-rates-sync.js`（阶段12 C1） | 管理台「税率」Tab 的「社保/公积金缴费基数下限」，全国口径（最终生效值） |

**常量定义**（运行时会被 ② 覆盖，**不要缓存进局部常量**）:
- `MIN_SOCIAL_SECURITY_BASE`：社保缴费基数最低标准
- `MIN_HOUSING_FUND_BASE`：住房公积金基数最低标准

> 出厂值与 §8.2 的表单初始默认基数一致（**默认值即最低标准**）：输入等于该值不提示，低于才提示。

**关于已回退的第三层（改这里时必读）**：回退前 C2 还有一层「按所选参保城市覆盖」—— `city-social-sync.js` 监听 `euriskotax:tax-rates-updated`，在 C1 把全局量写回全国口径之后重新施加城市口径，保证城市口径是最终生效值。该模块与其时序约束已随 v1.17.0 一并移除；**日后若要恢复分档，必须按同样方式在其后重新施加，否则用户看到的基数下限会静默退回全国口径**（这类故障用户只会看到口径不对，定位代价很高）。

**代码实现**: `src/js/calculation/tax-constants.js`（出厂值 + 分层契约注释）；后端出厂基线见 `server/src/services/taxRateService.js` 与 `server/src/services/citySocialService.js`；公开端点见 §8.4

### 8.2 默认值设置

所有社保缴费基数与住房公积金基数输入框默认值统一为 **7546 元/月**（公积金基数与社保基数保持一致）。

> 说明：这里刻意**不做「按城市自动回填下限」**——静默改写用户已填数字会造成「我明明输了 6000，怎么变成 6821」的困惑。城市参数只用于**校验提示**（低于该城市下限时提示），输入值始终由用户掌控。

| 输入框ID | 默认值 | 页面 |
|---------|--------|------|
| `social-security-base` | 7546 | 正向计算 |
| `housing-fund-base` | 7546 | 正向计算 |
| `reverse-social-security-base` | 7546 | 反向倒算 |
| `reverse-housing-fund-base` | 7546 | 反向倒算 |
| `business-social-security-base` | 7546 | 经营所得 |
| `business-housing-fund-base` | 7546 | 经营所得 |

| `tax-profile-housing-base` | 7546 | 税务档案默认值 |

**初始化计算**: 页面加载时自动使用默认基数（7546）计算社保与公积金金额，派生结果：
- 养老保险：基数 × 8% = 603.68
- 医疗保险：基数 × 2% = 150.92

### 8.3 基数验证

**验证规则**: 当用户输入的基数大于0但低于最低标准时，显示红色警告提示。

**验证函数**:
- `validateSocialSecurityBase(prefix)`: 验证社保缴费基数
- `validateHousingFundBase(prefix)`: 验证住房公积金基数

**参数说明**:
- `prefix`: 前缀，用于区分正向计算（空）和反向倒算（`reverse`）

**警告提示**: `⚠️ 当前基数低于最低标准 <最低标准> 元/月`（v1.17.0 起统一为**全国口径**；各地口径差异改由顾问在留资后人工核对，见 §8.4）

**代码实现**: `src/js/calculation/helper-functions.js`（读取全局量，不缓存）

**事件绑定**: 在基数输入变化时触发验证：
- `social-security-base`: `input` 事件
- `housing-fund-base`: `input` 事件
- `reverse-social-security-base`: `input` 事件
- `reverse-housing-fund-base`: `input` 事件

**代码实现**: `src/js/app.js`（初始化与事件绑定）

### 8.4 城市社保参数库（阶段14 C2，端上已于 v1.17.0 回退）

**当前状态**：端上**不再让用户选参保城市** —— `src/js/ui/city-social-ui.js` 与 `src/js/data/city-social-sync.js` 已删除，三页社保区块下方没有城市下拉，三页「缴费比例」是**用户自填的数字框**（默认 5%，各地 5%~12% 不等，按自己参保地改），基数提示统一按 §8.1 的全国口径。经营所得页的「缴费基数 / 缴费比例」同样是活控件：社保基数 × 养老/医疗/失业比例、公积金基数 × 公积金比例 → 各自月度金额（改基数或比例即覆盖金额，用户之后仍可手改金额）。城市改由**留资表单收集**（`Lead.city`），顾问按当地口径人工核对后给结论。

**为什么回退**：参数库的初衷是让端上按城市分档校验基数下限，但它要求用户在计算页先做一次「我该选哪个口径」的判断 —— 多数用户并不确定，选错就直接得到错误结论，多一步选择还会压低留资转化。把这步挪到留资之后（由顾问核对）信息质量更高。

**保留的部分（后台能力，端上不消费）**：

| 保留项 | 位置 |
|------|------|
| 参数库 + 版本化快照 / 回滚 | `CitySocialConfig` 模型、`server/src/services/citySocialService.js` |
| 公开只读端点 | `GET /api/config/city-social?since=<revision>`（见 api-reference §10.4） |
| 管理台维护入口 | 「社保基数」Tab（增删改 / 出厂基线 / 回滚另存 / 可选公告联动） |

保留的理由：后续「社保基数」SEO 落地页需要真实城市口径（见 `docs/development/seo-landing-plan.md`），参数库 + 公开端点正是这个能力；要恢复端上分档，按 git 历史回滚那两个前端模块并在 `index.html` 重新引入即可 —— **记得同时恢复 §8.1 的时序约束**，否则口径会被 C1 静默写回全国值。

**服务端校验（改参数时必读）**：`code` 小写字母开头、仅 `a-z0-9_-`、长度 2-32；`name` ≤50 字、`note` ≤200 字；`*BaseMin` 必填且 ≥ 0，`*BaseMax` 为 `null` 表示**不设上限**（JSON 不支持 `Infinity`，故不用它传输）；`housingFundRateOptions` 去重升序、最多 6 项、缺省 `[5,7]` —— **北京 5%–12% 整数是 8 档，直接提交会被 400 拒绝，需要全量档位时先确认是否放宽该上限**；`national` 为**兜底城市**不可删除；`defaultCity` 必须存在于列表中；版本号唯一，且上限不得低于下限。前端校验只为即时反馈，**后端才是安全边界**（详见 `docs/api/api-reference.md` §10.4）。

## 9. 反向倒算目标选择规则

### 9.1 二选一机制

**规则**: 按目标税额倒算方式下，"希望缴纳的税额"和"希望到手的金额"二选一填写，优先使用税额。

**下拉选项**:
- `tax`: 希望缴纳的税额（默认）
- `net`: 希望到手的金额

**交互逻辑**:
- 选择"希望缴纳的税额"时，显示税额输入框，隐藏到手金额输入框
- 选择"希望到手的金额"时，显示到手金额输入框，隐藏税额输入框

**代码实现**: `index.html` 第1616-1649行，`index.html` 第3520-3531行

### 9.2 数据收集逻辑

**收集规则**: 根据下拉选项的值来设置 `fixedTax` 和 `fixedNet`：

```javascript
const targetType = document.getElementById('reverse-target-type')?.value || 'tax';
if (targetType === 'tax') {
    fixedTax = parseFloat(document.getElementById('reverse-fixed-tax')?.value) || 0;
    fixedNet = 0;
} else {
    fixedNet = parseFloat(document.getElementById('reverse-fixed-net')?.value) || 0;
    fixedTax = 0;
}
```

**前端验证**: 当两个字段都填写时，抛出错误提示："希望缴纳的税额和希望到手的金额请只填写一项"

**代码实现**: `src/js/calculation/tax-calculator.js` 第1478-1492行

### 9.3 计算逻辑优化

**均衡模式修复**: 按目标税额倒算均衡模式使用二分法计算的基准值，而非档位中间值。

**修复前**:
```javascript
// 使用档位中间值
modeTaxableIncome = (minTaxableIncome + maxTaxableIncome) / 2;
```

**修复后**:
```javascript
// 使用二分法计算的基准值
modeTaxableIncome = baseTaxableIncome;
```

**涉及函数**:
- `calculateFromTargetTax()`: 综合所得按目标税额倒算
- `calculateBusinessFromTargetTax()`: 经营所得按目标税额倒算
- `calculateFromMonthlyNet()`: 综合所得按月度税后收入倒算
- `calculateBusinessFromMonthlyNet()`: 经营所得按月度税后收入倒算

**代码实现**: `src/js/calculation/tax-calculator.js` 第1186、1056、1815、1941行

### 9.4 差异字段修复

**问题**: 在到手金额模式下，`taxDifference` 字段显示 `actualTax - targetTax`，但 `targetTax` 为0，结果无意义。

**修复**: 在到手金额模式下，`taxDifference` 改为显示到手金额差异：
```javascript
taxDifference: (totalIncome - actualTax) - targetNet
```

**涉及函数**:
- `calculateFromTargetTax()`: 综合所得
- `calculateBusinessFromTargetTax()`: 经营所得

**代码实现**: `src/js/calculation/tax-calculator.js` 第1286、2118行
