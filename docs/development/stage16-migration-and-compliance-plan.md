# 阶段16：迁移与合规升级

*创建：2026-09-13 · 状态：⏳ 待开始（**硬前置：ICP 备案通过**；备案性质已定：**企业（单位）主体 · 有限责任公司**，见 §2.1 / §2.2）*

> **编号说明**：本阶段原为「阶段15」，因新增 [阶段15：税务计算能力扩展](./stage15-multi-tax-plan.md)，本阶段顺延为**阶段16**。历史上从「阶段12」拆出的支付体系与 B 端 API 一并落在这里。

## 1. 立项背景

阶段12 拆分时，**支付体系**与 **B 端 API** 因 **ICP 备案阻塞**被移出，与「迁腾讯云国内节点」「微信小程序」合并为独立的迁移与合规阶段。当前站点部署在境外（Zeabur 域名），国内搜索引擎收录与排名受备案与本地化因素影响，官方支付与小程序均需境内备案主体与资质。

**为什么不能提前**：备案是国家级审批排队（3–5 周），且支付 / 小程序主体资质依赖备案完成。**为什么可以与阶段15 并行**：16A/16B/16C 只依赖备案，不依赖多税种；只有 **16D（B 端 API）额外依赖阶段15 的 15B 企业税种**。

## 2. 前置：ICP 备案（并行线，⏳ 待启动）

> **口径来源**：腾讯云官方《首次备案》操作指引（2026-07-23 版）+ 广东省通信管理局《增值电信业务经营许可申请指南》（2025-02）。分省细节以**各地管局规则**为准。

### 2.1 决策：备案**企业（单位）主体**，不备案个人 ✅ 已定

| 维度 | 个人备案 | 企业（单位）备案 | 本站适用性 |
|---|---|---|---|
| 网站/服务名称 | 不得含企业字号、行业/产品词 | 按营业执照与实际业务命名 | ❌「个税 / 税务 / 财务」类词个人备案极易被驳回 |
| 内容性质 | **不能卖东西、不能投广告、不能收会员费** | 可电商 / 内容付费 / 广告 | ❌ 专业版 + `ProCode` 兑换码属收费行为 |
| 前置审批类型 | **个人备案无此选项** | 单位备案才有 | ❌ 结构性差异 |
| 单订单备案数量 | 最多 **1 个**网站/域名 | 最多 **10 个**网站/域名 | ❌ 后续要做多税种落地页矩阵 |
| 微信小程序 | 个人主体**不能开通微信支付** | 企业（或个体工商户）可开通 | ❌ 16C 直接卡死 |
| 官方支付 | 无法申请商户号 | 需营业执照申请商户号 | ❌ 16B 直接卡死 |
| 转换成本 | 个人 → 企业须**先注销再重备**，站需关停 | — | ❌ 一次性选对，不留返工 |

### 2.2 主体形态：**有限责任公司**（而非个体工商户）

- 个体工商户可满足「备案 + 小程序 + 支付」，但**办不了经营性 ICP 许可证**（法规要求主体为「依法设立的公司」），也难支撑 16D 的 B 端签约开票。
- 有限责任公司：股东责任有限、可开增值税发票、可申请 ICP 许可证 → 与 16D 方向一致。

### 2.3 是否需要**经营性 ICP 许可证**（增值电信业务经营许可 · B25）

- **判断标准**：是否「通过互联网向上网用户**有偿**提供信息服务」。专业版付费**严格来说落在经营性范畴**。
- **实务现实**：付费会员 / 内容付费站绝大多数只做非经营性备案 + 会员付费，规模平台化后才会被要求办证（**风险存在但不必然触发**）。
- **本项目路线**：**先做非经营性 ICP 备案上线**（周期短、零费用），付费包装为「服务 / 咨询费」性质；等 **16D 售卖 B 端 API（明确经营性）** 或付费规模化后，再评估办证。
- **办证门槛**（广东管局）：主体为依法设立的公司；**省内经营注册资本 ≥ 100 万元**（跨省门槛更高，以管局为准）；**最近一个月为 3 名负责人缴纳社保**；必要场地设施与技术方案；网络与信息安全保障措施；未列入失信名单。不收费，5 日内决定受理、**60 日内**审查完毕。

### 2.4.1 域名选型（**定死，不可再换**）

**决策 D4 的代价**：PWA 的 `localStorage` / Cache Storage 绑定域名，换域名 = 全部用户本地历史丢失 → 一期选定后不再更换。

| 方案 | 候选 | 优点 | 缺点 |
|---|---|---|---|
| **A（推荐）** | `euriskotax.com` | 与现有品牌 / 页面标题 / `sitemap.xml` / share-img 完全一致；迁移只换域名，`/seo/*.html` 路径结构不动 | 10 字母、音节多，中文用户口头难传播 |
| B | `euriskotax.cn` / `euriskotax.com.cn` | 国内信任度高、备案常见 | 品牌分散；`.cn` 后缀虽已收录但不如 `.com` 通用 |
| C | 短拼音业务名（如 `geshuibao` / `shuibao` 类） | 中文用户易记易输入、利于口头传播 | 需先查可用性（多半被注册或溢价）；与现有品牌 / SEO 资产脱钩 |

**动作**：
1. 在腾讯云域名注册页查可用性（候选 A + B 一并查）
2. **主域取 `.com`**，同时**防御性注册** `.cn` 并指向主域 301（品牌保护 + 防钓鱼）
3. **域名所有者填公司全称**（whois 实名主体 = 备案主体）
4. 已有 `euriskotax.zeabur.app` 继续作为**预发环境**（境外无需备案），不冲突（§2.7-1）

> **落地页结构不用改**：现有 SEO 落地页走**子目录**（`/seo/bonus-tax.html` …），单域名即可覆盖；后续若某税种要独立品牌，再启用「新增网站」（单位备案可备 10 个）。

### 2.4.2 「服务名称」命名方案（**最容易驳回的一环**）

**硬性规则**（腾讯云《网站命名建议》）：

| 规则 | 说明 |
|---|---|
| 字数 | **≥ 3 个字**（一个字母或数字算一个字；`( )` `-` 不计） |
| 字符 | **不能是纯数字、不能是纯英文**；仅允许 `( )` `-` 三种特殊符号，其它符号（如 `&` `·` `—` `：`）一律不行 |
| 禁用词 | 非国家级单位禁用「中国 / 中华 / 国家 / 人名 / 地名」；禁用敏感词（如反腐、赌博） |
| 内容相关性 | 名称须**能体现网站内容**；企业**推荐用公司全称或简称**（通过率最高，且允许多个网站同名） |
| 地名层级 | 单位备案：**主体名称中的地名须 ≥ 网站名称中的地域** → 公司名无城市，网站名称里也别放城市 |
| 金融类 | 涉及金融类内容会被建议先办**省金融办专项审批** → 名称与备注须主动界定「计算工具」边界 |
| 公示性 | 名称**会被公示**；备案通过后再改需走**变更备案** → 一期定死 |

**候选名称（按通过率排序）**：

| 序 | 候选 | 依据 | 风险 |
|---|---|---|---|
| 1 | **公司全称或简称**（如「欧瑞斯科科技」「欧瑞斯科网络科技」） | 官方推荐，通过率最高；多站可同名 | 需与营业执照字号一致 |
| 2 | **品牌 + 业务**：`EuriskoTax 个税助手` / `Eurisko 个税计算工具` | 含中文、体现内容、保留品牌 | 略长 |
| 3 | **纯中文业务名**：`个税计算助手` / `个税规划工具` / `工资个税速算` | 最贴合内容，最易过 | 与品牌弱关联 |
| ✗ | `EuriskoTax`（**纯英文**） | — | **必被退** |
| ✗ | 含「税筹 / 节税 / 避税 / 理财 / 金融 / 投资」 | — | 金融类识别风险，与「不构成税务建议」定位冲突 |
| ✗ | 含公司名里没有的城市（如「杭州…」） | — | 违反地名层级规则 → 退 |

**推荐**：**方案 2 或 3**（如 `EuriskoTax 个税助手`）；若公司字号本身含「税务 / 科技」类词，直接用**公司简称**最稳。

**备注栏必须写**（勾「其他」时管局强制执行，同时主动界定边界）：

> 本站为个人所得税计算工具，提供综合所得、经营所得、分类所得在线测算与结果导出，不涉及资金收付、支付结算、税务代理及投资理财业务；页面均标注「本测算结果仅供参考，不构成税务建议」。

### 2.7 高频驳回点（本项目相关，逐条规避）

1. **备案期间该域名不得解析到境内服务器对外提供服务**（管局核查，解析会被驳回 / 要求整改）→ 用**双域名策略**：老域名继续在 Zeabur（境外无需备案）过渡，**新域名**走备案，通过后再切（对齐 16A 灰度切流）
2. **域名所有者必须与备案主体一致**（企业备案 → 域名须在公司名下）
3. **备案省份必须按营业执照注册地**选择，不可随意选
4. **初审电话必须能接通**（安排专人留意陌生来电，否则直接驳回）
5. **网站负责人需真人核身**（微信扫码 + 人脸视频）→ 建议法定代表人兼任，省一份授权书
6. **服务名称会被公示**，避免引起误解的词，须与实际业务一致
7. **公司改名 / 法人变更均需做备案变更** → 一期把主体信息定死
8. **付费相关内容在备案通过前不宜公开**（个人/企业备案都不承载经营性业态的公开宣传，见 §2.3 路线）
9. **服务名称写成纯英文被退** —— `EuriskoTax` 这类纯英文名称违反「不能是纯数字 / 纯英文」硬规则，必须含中文（→ §2.4.2）
10. **服务内容误勾「网上支付」类 → 触发金融类专项审批** —— 即使有会员付费也**绝不要勾**「网上支付 / 网上银行 / 网上炒股·股票基金 / 网络购物」，勾了会被要求补省金融办审批件 → 直接退回（→ §2.4.3-B）
11. **域名实名认证未满同步期就提交** —— 腾讯云注册域名须满 **3 个自然日**、非腾讯云注册须满 **3 个工作日**（→ §2.4-2）
12. **域名后缀未被工信部收录** —— 提交时会提示「该域名后缀不支持备案」，选域名前先到 `domain.miit.gov.cn` 核对
13. **手机号复用 / 订单并发** —— 一个手机号只能备案 **1 个主体**；同一腾讯云账号**同时只允许 1 个**进行中的备案订单
14. **名称中含公司名里没有的地名 → 退** —— 单位备案要求「主体名称中的地名 ≥ 网站名称中的地域」（→ §2.4.2）

> **纪律**：备案期间产品迭代**不受阻塞**——阶段15 与 15C 纯前端能力照常推进；§2.4 的材料与域名准备可在等待期内完成。

## 3. 任务拆分

### 16A 迁移腾讯云国内节点（Zeabur 转预发）

### 16B 官方支付（微信 / 支付宝）

| 项 | 内容 |
|---|---|

| 验收 | 支付 → 权益即时生效；重复回调幂等；退款后权益正确回收 |
| 硬前置 | ICP 备案 + 支付商户资质 |

### 16C 微信小程序

| 项 | 内容 |
|---|---|

### 16D B 端 API 开放（**依赖阶段15 多税种**）

| 硬前置 | 依赖 **阶段15 的 15B 企业税种**（没有企业税种就没有可售卖能力） |

## 4. 验收与守护

- **生产等价演练**：动过 `server/prisma/schema.prisma` 或迁移时，必须跑 `npm run verify:pg`（本地 PostgreSQL 演练 `generate → migrate deploy → 起服务`，与线上容器同序）。
- **线上指纹**：切流前后均以 `tools/ops/ops-check-prod.ps1` 核对（页面 / 登录 / 内容端点 / 线索端点 / 兑换码端点等）。
- **发布纪律**：一律走唯一合规入口 `tools/ops/ops-publish.ps1`（本地门禁全绿 → 提交 → 推送 → 线上核对 → 自动打标签）。
- **口径同步**：`npm run verify:release` 校验版本五处与文档口径一致。

## 6. 风险与合规

| 风险 | 应对 |
|---|---|
| 备案排队超预期 | 阶段15 与 15C 纯前端能力照常推进，不空转；材料准备前置完成 |
| **备案性质 / 主体选错导致返工** | 已定 **企业（单位）主体 · 有限责任公司**（§2.1 / §2.2）；个人备案不得收费、小程序不能开支付、个人 → 企业须先注销再重备，代价极高 |
| 备案期间域名解析冲突 | **双域名策略**：老域名留 Zeabur 过渡，新域名走备案，通过后再切（§2.7-1） |
| 域名所有者与主体不一致 → 驳回 | 备案前先完成域名过户到公司名下（§2.7-2） |
| 数据迁移丢失 | 迁移前全量备份；灰度期双写 / 双环境对照；保留回滚预案 |
| 支付回调幂等 / 安全 | 验签 + 幂等键 + 事务化权益发放；对账报表兜底 |
| 小程序与 Web 算法漂移 | 强制复用同一纯函数层，禁止小程序端另写一份算法 |
| B 端 API 被滥用 | API Key + 限流配额 + 按次计费；Swagger 明确使用边界 |
| 经营性合规风险（付费业态） | 先做非经营性备案上线，付费包装为「服务费」性质；16D 售卖 API 后评估办 ICP 许可证（§2.3） |
