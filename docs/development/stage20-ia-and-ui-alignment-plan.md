## 0. 一页纸结论

| # | 结论 | 依据 |
|---|---|---|
| 1 | **顶部导航与底部导航不是两个导航，是同一个导航的两种投影** —— 现状已由 `syncNav()` 一份状态驱动（`toolbox-ui.js:1802`）。要解的重复不在两端之间，而在**顶栏 vs Tab**（顶栏里的「个人中心」「帮助」与 Tab 目的地撞车） | 实测 `index.html:360` / `:416` / `:2549` |

### 1.5 诊断：五类重复 + 三个断点

**重复（同一目的地有多条稳定路径）**

| ID | 重复 | 现状两侧 | 处理 |
|---|---|---|---|
| R1 | 「个人中心」 | 顶栏用户菜单（`index.html:398`）≡ 底部 Tab「我的」 | 顶栏菜单只留**账号动作**（切换账号 / 退出），去掉目的地 |
| R2 | 「使用帮助」 | 顶栏 `#help-btn` ≡ 我的页「使用帮助」卡 ≡ 助手 FAB | 顶栏帮助按钮撤掉（助手 + 我的页已两处） |
| R3 | 「税务节点/截止」 | 首页「我的税务资产」待办 + 首页「税务提醒」≡ 我的 → 税务日历（三者同源：`home-mission.buildTodos`） | 首页合成**一张**「接下来要办」，详表只在「我的 → 税务日历」 |
| R4 | 「历史 / 台账」 | 首页「我的方案与台账」+ 最近算过 ≡ 我的 → 计算历史 / 我的台账 | 首页只留「继续上次」最多 3 条**动作**，清单归「我的」 |
| R5 | 「关于本站」 | 首页底部长文（`index.html:607`）≡ 我的 → 关于我们 | 首页删，只留一行「数据不出本机」的信任标签 |
| R6 | 「分类维度」 | 首页身份卡（6 张）与工具页场景组（5 个）是两套平行分类 | 首页身份降为**一行 chip**（设默认视角），分类只保留在工具页 |
| R7 | 「搜索」 | 首页搜索入口卡 ≡ 工具页搜索框 | 升为**常驻搜索**：桌面进顶栏、手机在首页顶部；工具页搜索框保留（同一组件） |

**断点（不是重复，是结构与商业不匹配）**

| ID | 断点 | 后果 |
|---|---|---|
| B1 | 21 个完整测算在工具页**末位 + 默认折叠** | 核心卖点（全税种完整测算）与付费值厚度对浏览用户不可见 |
| B2 | 首页 10 个区块平权堆叠，其中 5 个是「我的」内容的镜像 | 首屏到第一个可点入口要滚两屏；首页「什么都有一点、都不完整」 |
| B3 | 我的页 13 张卡一维罗列；sub-nav「返回」与底部 Tab 语义冲突 | 高频四项（历史/台账/档案/日历）与低频五项同权，找不到；「返回」不知返回何处 |

### 2.2 依赖与交互关系（谁依赖谁、数据往哪流）

| 关系 | 方向 | 说明 |
|---|---|---|
| 注册表 → 渲染层 | `tool-registry` → `toolbox-ui` / `deep-wizard-ui` / `home-ui` | **单向**。页面不持有工具清单；新增税种不改 `index.html`（阶段17 已验证） |
| 注册表 → 政策层 | `tax-registry` → 结果卡 `#dw-policy-stamp` / 速算器徽标 | 时效与版本号**只有一个来源**，渲染层不自带数字（v1.103.0 起的硬规矩） |

## 3. 导航定位：顶部 vs 底部（去重规则）

### 3.1 四层导航模型

| 层 | 载体 | 回答的问题 | 允许放什么 | 不允许放什么 |
|---|---|---|---|---|
| **L1 全局** | 顶栏（全端 56px） | 「我是谁 / 在哪个主体 / 什么版本 / 环境动作」 | 品牌、搜索、版本 pill、主体切换、主题、安装、登录/账号菜单 | **任何 Tab 里已有的目的地** |
| **L2 目的地** | 顶部 Tab 行（≥768px）/ 底部 Tab 栏（<768px） | 「我要去哪一页」 | 最多 5 个**平级页面**，且必须是名词（首页/工具/我的） | 动作（计算/助手/分享）、弹层、二级页 |
| **L3 任务** | 页内 sub-nav / 步骤条 / 预览条 | 「这一步干什么、怎么退出」 | 返回、步骤指示、吸底结果条 | 跨页跳转 |
| **L4 情境** | 助手 FAB / 结果页情境入口 | 「我现在有个具体问题」 | 随内容出现的动作 | 常驻占位 |

### 3.2 两端差异（形态，不是功能）

| 维度 | 电脑端网页 | 手机端（微信 H5 / 小程序） |
|---|---|---|
| Tab 位置 | 顶部 Tab 行（拇指够不到底部，且底部通栏浪费横向空间） | 底部 Tab 栏（拇指热区） |
| 顶栏 | 完整（品牌名 + 搜索 + 全部图标） | 精简（品牌 + 搜索 + 版本 pill；其余收进「我的」） |
| 助手 | ≥1280px 推开式侧栏（边看边问） | 悬浮球（FAB），可被结果条顶开 |
| 状态源 | **同一份 `syncNav()`**，两端只是两种投影 | 同左 |

> 硬规矩不变：**两端不提供对方没有的功能，只提供对方做不好的呈现方式**（`ui-ux-master-plan.md` §5.4）。

### 3.3 去重三条规则 + 现状违例

1. **一个目的地只有一条稳定路径** —— 其他位置只允许出现「直达动作」（跳过去并顺带做一件事，如「补填子女教育」直接开速算器）。
2. **顶栏不重复 Tab** —— Tab 已覆盖的页面，顶栏与菜单里一律不再出现。
3. **同一功能全局 ≤ 2 处入口** —— 现状「使用帮助」3 处、升级入口 2 处（顶栏 pill + 我的页，合规）。

| 违例 | 现状处数 | 目标 |
|---|---|---|
| 个人中心 | 2（顶栏菜单 + Tab） | **1**（Tab） |
| 使用帮助 | 3（顶栏 + 我的页卡 + 助手） | **2**（我的页卡 + 助手） |
| 税务日历/截止 | 3（首页资产待办 + 首页税务提醒 + 我的日历） | **2**（首页一张摘要 + 我的日历详表），且首页那张是**动作**不是清单 |
| 历史/台账 | 2 处清单（首页卡 + 我的页） | **1 处清单**（我的）+ 首页最多 3 条动作 |
| 搜索 | 2 处入口（首页卡 + 工具页框） | **1 个组件**，两处挂载（桌面顶栏、手机首页顶部 + 工具页） |
| 升级入口 | 2（顶栏 pill + 我的页权益条） | **保持 2**（阶段14 入口收敛约束，不增不减） |

## 4. 首页重构：模块与排列顺序

### 4.1 排序原则

> **按「这个用户此刻最可能推进的动作」排序，不按功能分类排序。**
> 现有 10 个区块是按「功能有什么」堆出来的（身份是一种分类、日历是一种分类、历史是一种分类），
> 用户读到的却是「一堆都跟我有关、但不知道先点哪个」。

动线：`我是谁/我要什么（Hero）→ 我遇到了什么事（事件卡）→ 我现在该办什么（待办）→ 接着上次（续算）→ 顺便看看（呼吸区）`

### 4.2 新顺序（两端同序，仅密度不同）

| 新序 | 模块 | 相对现状 | 依据 |
|---|---|---|---|
| ① | **搜索条**（常驻，非卡片） | 现状「搜索入口卡」升级；桌面同时进顶栏 | 41 个入口早已越过「搜索优先于浏览」的 25 阈值（§5.2） |
| ② | **Mission Hero**（首访 / 有历史 / 临近节点 三态） | 保留，上移为唯一首屏焦点 | 首屏只回答一个问题：「你现在该办的事」 |
| ③ | **我遇到了什么事**（9 张事件卡横轨） | 保留 | 转化主力；「认得自己的事」比「说得清身份」容易 |
| ④ | **接下来要办** ★ 新建 | = 原「我的税务资产」待办 + 原「税务提醒」+ 原「漏填提醒」三合一 | 三条都是「现在有个截止/有个没填」，拆成三张卡只是三种分类视角 |
| ⑤ | **身份 chip 一行**（6 个） | 原「我是谁」整卡 → 一行 chip | 身份是**设置默认视角**，不是导航；占整卡会与工具页场景组形成两套分类 |
| ⑥ | **继续上次**（最多 3 条动作） | 原「我的方案与台账」卡精简 | 清单归「我的」，首页只留「接着算」这一个动作 |
| ⑦ | **呼吸区**（今日税感 + 小贴士） | 保留，移至页尾 | 看了有用、不看不阻塞 |
| — | ~~关于本站（长文）~~ | **删除**，只留一行「41 个场景 · 数据不出本机」信任标签 | 与「我的 → 关于我们」重复（R5） |

**由此首页从 10 区块降到 7 区块**，且 ④⑥ 两类「我的内容镜像」从「清单」降级为「动作」。

### 4.3 关键模块规格

**④ 接下来要办（新建）**

```
┌────────────────────────────────────────┐
│ 接下来要办                    2026 年   │
│ ① 个税汇算                剩 87 天  ›   │   ← 来自 buildTodos（日历 × 已算过的工具）
│ ② 子女教育还没填                    ›   │   ← 来自 tax-profile.completeness
│ ③ 上月台账还没归档                  ›   │   ← 来自 ledger（有台账行才出现）
└────────────────────────────────────────┘
```
- 三条硬规矩（沿用现状注释里的判断，不推翻）：
  - 一项都没有 → **整卡不出现**（新客看到的是干净首页，不是「你漏了 5 项」的噪音）；
  - 每条出口**直达对应速算器**，不跳「我的 → 我的情况」（免登录也能补，算完的值会被档案吸收）；
  - **不写金额** —— 子女数、分摊方式都不知道，硬算出来的「可能多缴 ¥1,200」是假的。
- 排序：按 `daysLeft` 升序；无截止的（漏填/台账）排在截止类之后。

**⑤ 身份 chip**：点 = 设为默认视角（就地，`identity-pref.set()`）；不再出现「看这类工具 ›」（那颗按钮是它变成第二套分类的原因，需要跳工具页时靠 ① 搜索和 Tab）。

**⑥ 继续上次**：最多 3 条，每条 = 「工具名 · 相对时间」+ 一颗「继续 ›」；「全部 ›」出口指向「我的 → 计算历史」。

## 5. 工具页排版

### 5.1 三个改动

| # | 改动 | 理由 |
|---|---|---|
| T1 | **完整测算从「末位折叠组」提为并列类型筛选**：`全部 41 / 速算 20 / 完整测算 21` | 21 个完整测算 = 核心卖点 + 付费值厚度（§1.5⑥），藏在末位折叠组等于对浏览者不存在。**筛选是互斥视图，不是混排** —— 因此不违反「混排会让同组出现两个算工资入口」的旧约束 |
| T2 | **场景组从纵向列表改网格**：桌面 2–3 列、分组头 sticky；手机保持单列折叠 | 桌面三要素的第一条就是信息密度（§4.2）；现状 1024px 容器里仍是单列列表 |
| T3 | **顶部加 sticky 场景锚点 chip 条**（仅桌面，横向一行，不做左侧树） | §5.3 否决的是「左侧深层级树状导航」；横向锚点条是**跳读**不是**分类树**，成本极低 |

### 5.2 结构（两端）

```
[搜索框 ————————————————————————]
[全部 41] [速算 20] [完整测算 21]        ← T1（互斥筛选，默认「全部」）
[为你推荐（上班族） chip  ×]             ← 身份只置顶，不筛选（现状 chip 保留）
──────────────────────────────────────
桌面：工资与到手 · 一次性 · 税优 · 社保 · 企业与经营   ← T3 锚点条（sticky）
  ┌────────┐ ┌────────┐ ┌────────┐
  │月薪个税 │ │年终奖   │ │谈薪倒算 │                ← T2 多列网格
  └────────┘ └────────┘ └────────┘
手机：▸ 工资与到手（5）   ← 单列 + 折叠头（现状）
```

- 「最近使用」保持默认展开（现状决策，回访快捷通道）。
- 筛选状态不写入 localStorage（会话级，避免下次进来以为是坏了）。
- 完整测算与速算器**同名入口不合并显示**：同一税种在「速算」与「完整测算」两个视图里各出现一次是正确的（它们是两种填法）。

## 7. 双端适配：电脑网页 vs 手机小程序

### 7.1 电脑端网页（≥768px，主力 1280–1440）

| 项 | 规格 |
|---|---|
| 导航 | 顶栏 56px sticky + 顶部 Tab 行（`md:block`），**无底部栏** |
| 容器 | `--c-default` 1024px（首页/工具页/列表）；`--c-narrow` 720px（表单页，守 65–75 字符行宽） |
| 工具页 | 场景锚点 chip 条 + 2–3 列网格 + sticky 分组头 |
| 速算器页 | **左「填写参数」sticky / 右「测算结果」实时联动**（现状已落地，保留） |
| 助手 | ≥1280px 推开式侧栏（不覆盖内容） |
| 输出 | 导出 PDF / CSV、打印、多方案并排对照 —— 桌面三要素「可交付」 |

### 7.2 手机端（<768px，微信内 H5 / PWA standalone）

| 项 | 规格 |
|---|---|
| 导航 | 底部 Tab 3 项（拇指热区）；顶栏精简（品牌 + 搜索 + 版本 pill） |
| 容器 | 全宽单列，`data-page-container` 提供底栏避让 padding（勿改宽度工具类） |
| 输入 | 分步 / 一次一问（完整测算向导）；速算器单列表单 + 吸底结果条 |
| 结果 | 结论优先 + 明细折叠 + 吸底动作条 |
| 输出 | 分享图（长按保存）；微信/PWA 内下载被拦时走「长图 → 复制文本」降级链（现状已实现） |
| 安全区 | 底部 `env(safe-area-inset-bottom)`；PWA standalone 顶部留状态栏高度 |

### 7.3 手机端「小程序」：形态判定（先说清事实）

> **当前代码库没有任何小程序。**（无 `app.json` / `project.config.json` / `appid`，微信 JS-SDK 未接入；`manifest.json` + `service-worker.js` 说明形态是 **H5 + PWA** —— `ui-ux-master-plan.md` §1.5① 已核实）

因此「手机端小程序」有三种可能的解读，**成本与结论完全不同**：

| 解读 | 做什么 | 结论 |
|---|---|---|
| (a) 口语化的「在微信里打开的 H5」 | 只做微信内适配（降级链、安全区、分享） | ✅ **现状已覆盖**，补 §7.2 安全区即可 |
| (b) 承接端 SEO 站 + 微信为渠道 | 对齐跳转与留资衔接 | ✅ 现状方向（商业模型已定） |
| (c) 真做原生微信小程序 | 重写一套 + 受两条平台红线夹击 | ⚠️ **不建议**。iOS 虚拟支付限制会直接掐断后期变现（§1.5②） |

**本方案采用 (a)+(b)，并把「小程序外壳」作为可选 P4**：真要做，**只做适配层，不动业务层**。

### 7.4 小程序外壳适配层（若真要做，只有这四处）

| 能力 | 网页现状 | 小程序差异 | 适配做法 |
|---|---|---|---|
| 存储 | `localStorage`（history/ledger/template/entity/param-memory 全走它） | 无 `localStorage`，只有 `wx.setStorageSync`（同步、单 key 1MB、总 10MB） | 抽 `StorageAdapter`（get/set/remove），业务层只认适配器；**不要逐处改 `localStorage`** |
| 导出 / 分享图 | `html2canvas` + `jsPDF`（依赖 DOM 与 Canvas 2D） | 无 DOM；只能 `wx.canvasToTempFilePath` 或服务端合成 | 导出走**服务端渲染 PDF**（已有 `server/`），分享图走小程序 canvas 绘制；`Capture` 层加第二实现 |
| 导航 | 自绘顶栏 + 自绘 Tab | 微信原生导航栏 + 右上角胶囊；`app.json` 的 `tabBar` 最多 5 项、图标 81×81、无文字外图标 | 顶部 Tab 行 → 页面内自绘或原生 tabBar；**自绘悬浮元素必须避开胶囊右侧与底部 tabBar** |
| 支付 / 权益 | 站外收款 + 兑换码（`ProCode`） | iOS 端不得展示任何购买/价格/引导外链 | **小程序内不放任何付费入口**，只放「在浏览器打开」；兑换码流程放在 H5 侧 |

> 三条不可越：① 小程序内不放二维码 / 加微信式私域引导（平台严打）；② 不在 iOS 端展示价格与购买；③ 不新增第二套计算逻辑（能力层双端共用，见 §2.2）。

### 7.5 差异对照总表

| 维度 | 电脑端网页 | 手机端（H5 / 小程序） |
|---|---|---|
| 场景 | 办公室、要给老板/客户看 | 碎片时间、自己先算一个数 |
| 主导任务 | 填全 + 对照 + 交付 | 快速得到一个数 + 分享 |
| 导航 | 顶部（Tab 行 + 顶栏） | 底部（Tab 栏）+ 精简顶栏 |
| 单页信息量 | 多列、不折叠、同屏对照 | 单列、折叠、一次一问 |
| 结果呈现 | 输入与结果同屏、明细全展开 | 结论优先、明细折叠、吸底条 |
| 交付物 | PDF / CSV / 打印 | 分享图 / 长图 / 复制文本 |
| 助手 | 侧栏（边看边问） | 悬浮球（随手问） |
| 搜索 | 顶栏常驻 | 首页顶部 + 工具页 |
| 付费入口 | 顶栏 pill + 我的页权益条 | 同（小程序内不放） |

## 8. 商业框架对齐

沿用 `ui-ux-master-plan.md` §1.5 的**两阶段模型**，本次改动全部落在「不锁死后路」的一侧：

| 阶段 | 目标 | 本次改动的服务方式 |
|---|---|---|
| 前期（引流 → 私域） | 拉 `calc_done` 与 `lead_submit` | 首页动线缩短（首屏即可点）→ 激活；完整测算提为并列筛选 → 深度内容曝光 |
| 后期（工具自收费） | 专业版兑换 / 报告 | **不新增、不减少付费点**；只保证「权益进度条」在「我的」头部可见 |

三条不越的红线（沿用既有铁律）：
1. **计算过程零门禁** —— 不因未登录/未付费拦任何一次计算；
2. **免费版可导出**（只是专业版更精美）—— 「导出要钱」是勒索感，会砸 SEO 口碑；
3. **升级入口全局 ≤ 2 处** —— 本次「我的页」头部合一后仍是 2 处。
