## 1. 背景

用户提出：把「使用软件的人的身份」从现在的多档收敛为两种（自然人 / 企业），并把这次改动记为一个**主版本节点（2.0.0）**，先只发测试公网。

现状调查后确认三件事：

1. **身份值域有四套，彼此不通信** —— 只有「身份卡」是对用户提问的那套，其余三套是内部口径；
2. **身份不参与任何计算**，唯一功能是决定工具页「为你推荐」这一屏（`toolbox-ui.js:536-543`）与几处文案；
3. 因此这次是**导航与文案层重构**，不是计算改造 —— 但对外语义变了（首访问句从「你是谁」变成「你给自己算还是替公司算」），按主版本记。

### 2.3 现有硬边界（本方案不得推翻）

1. **身份不是筛选**：41 个入口永远都能进（`identity-pref.js:5-11`）；
2. **身份不写计税档案**：两条线值域不同，混写会变成「拿导航选择改计税口径」（`identity-pref.js:15-18`）；

`tool-registry.js:4509` 的 `if (v.identity === 'flexible')` 是**社保工具自己的字段**（灵活就业 / 职工），与全局身份同名不同义。**全局重命名或收敛时不要动它。**

## 4. 语义定义

### 4.1 两个轴，别合并

| 轴 | 含义 | 归属 | 用途 |
|---|---|---|---|
| **立场轴（本次新增）** | 给自己算 / 替单位或客户算 | 身份卡 `KINDS`（`self` / `enterprise`） | 决定工具页默认推荐哪一组 |
| **纳税人身份轴（已有）** | 缴个税的主体 / 缴企税的主体 | `entity-store.js` 的 `kind`（company / individual / person） | 决定这笔税算在谁头上 |

### 4.2 kind 命名

| kind id | 显示名 | 一句人话 |
|---|---|---|
| `self` | 我自己 | 算自己的工资、劳务、经营所得，或自己持有的股权 |
| `enterprise` | 企业 | 替公司或客户算企税、增值税、发票与用工成本 |

**刻意不用 `person` / `company`**：`entity-store.js` 已占用这两个字符串（纳税主体），同名不同义必串线。

### 4.3 为什么不做「两步弹窗」

| 方案 | 点击次数 | 状态机 | 测试增量 | 判断 |
|---|---|---|---|---|
| 两步（先大类、再场景） | 3 次 | step + 返回态 + 「第 1 步不算数」歧义 | +6 条 | ❌ 6 张卡本来一屏放得下，收益只有「第一屏少 4 张」 |
| **一屏两组折叠（选定）** | 2 次（与现状相同） | `expandedKind` 一个变量 | +4 条 | ✅ |
| 单屏平铺 + 分组标题（全展开） | 2 次 | 0 | +2 条 | 备选，但 6 张卡分两组全展开，视觉上没「收敛」的感觉 |

折叠规则：**恒有一组展开**，点组头只切换、不收起到全关闭 —— 全收起会让「下一步」无处可点，用户会以为坏了。

## 5. 设计

### 5.1 数据模型（加一层，不改值域）

```
KINDS = [
  { id:'self',       name:'我自己', icon:'fa-user',     desc:'自己的工资、劳务、经营所得，或自己持有的股权' },
  { id:'enterprise', name:'企业',   icon:'fa-building', desc:'替公司或客户算企税、增值税、发票与用工成本' }
]

SCENARIOS（id / name / desc / tools 全部原样，只加 kind；数组顺序不变）
  employee  上班族              kind: self
  freelance 自由职业 / 兼职      kind: self
  owner     个体户 / 小店        kind: self
  finance   企业财务 / 会计      kind: enterprise
  executive 高管 / 股东 / 临近退休 kind: self     ← 由企业侧改正
  hr        HR / 薪酬           kind: enterprise
```

> **为什么 executive 归 self**：股权激励、离职补偿、年金、外派都是**个人所得**，是这个人给自己算；公司不会替他算。初稿把它放在企业侧是错的。
>
> **为什么个体户留在 self**：民法典下个体户是自然人；税法上它不缴企业所得税，穿透到业主按经营所得缴个税（企业所得税法第 1 条明确个独 / 合伙不适用）。把个体户单列成第三类是图上的「非法人组织」口径，**按税法反而是错的**。

### 5.2 弹窗交互（一屏两组折叠）

```
┌ 身份弹窗（.modal-shell --lg；手机全屏）──────────────────────┐
│ 我是谁                                                     │
│ 先看你是给自己算，还是替公司或客户算；选一类，工具页会把它相关  │
│ 的工具排在「为你推荐」。其余入口一个不少，不选也照常用。        │
│                                                            │
│ ┌ ▾ 我自己            4 ┐  ← 组头：图标 + 组名 + desc + 计数 + 箭头
│ │ [上班族] [自由职业]     │
│ │ [个体户·小店] [高管·股东]│  ← 组内复用 .identity-pick 卡，2 列
│ └────────────────────────┘
│ ┌ ▸ 企业              2 ┐  ← 收起：只留组头
│                                                            │
│ 职务名称（选填）        公司名称（选填）                      │
│ 这两项只用于显示与推荐，不参与任何计算。                       │
│                                                            │
│ [暂时不填]                                    [下一步]        │
└────────────────────────────────────────────────────────────┘
```

状态规则：

| 动作 | 结果 | 落盘 |
|---|---|---|
| 打开（已有身份 `finance`） | `expandedKind='enterprise'`，预选 finance | 否 |
| 打开（无身份） | `expandedKind='self'`（`KINDS[0]`） | 否 |
| 点组头 | 切 `expandedKind`，箭头翻转，另一组卡片移除 | 否 |
| 点卡片 | `picked=<id>`，勾换到这张卡 | 否 |
| 点 × / 遮罩 | 关窗，`picked` / `expandedKind` 清空 | 否 |
| 点「暂时不填」 | `markOnboarded()`，身份保持未选 | 只写 onboarded |
| 点「下一步」 | `save({id:picked,title,company})` + 关窗 + `syncAll()` | ✅ 唯一落盘口 |

### 5.3 工具页分类：结构不变（含数据佐证）

分类条由 `toolbox-ui.js:458-471` 按注册表现算，**与身份无直接关系**：

```
[推荐 5] [最近 n] [工资 11] [一次性所得 13] [税优养老 4] [社保用工 5] [企业经营 8] [全部 41]
   ↑身份只决定默认落这一屏 + 这一屏的 5 个工具
```

本次改后逐项对照：

| 元素 | 变化 |
|---|---|
| 5 个分组 chip（工资 / 一次性所得 / 税优养老 / 社保用工 / 企业经营） | **不变**（`GROUPS` 驱动） |
| 「全部」41 = 速算 20 + deep 21 | **不变** |
| 「最近」 | **不变** |
| 「推荐」chip 内容与数量 | **不变**（按子场景取 5 个；一级只做分组标题，存盘仍是场景 id） |
| 「推荐」chip 文案 | **变**：`按身份推荐：企业财务 / 会计` → `按身份推荐：企业 · 企业财务 / 会计` |

**为什么不能把 5 组也二分**（逐组归属实测）：

| 分组 | 速算 / deep | 我自己侧要用它的身份 | 企业侧要用它的身份 |
|---|---|---|---|
| 工资与到手 | 5 / 6 | 上班族 | HR（发工资要算个税） |
| 一次性收入与特殊所得 | 5 / 8 | 自由职业、高管股东 | HR（离职补偿） |
| 税优与养老 | 3 / 1 | 自由职业、高管股东 | HR（年金） |
| 社保与用工 | 3 / 2 | 个体户、自由职业 | 企业财务、HR |
| 企业与经营 | 4 / 4 | 个体户（经营所得 / 增值税） | 企业财务 |

**没有一组只属一侧** → 按 kind 二分只会切出两个几乎同样大的桶，等于没分，还多一层点击。分类维度保持「工具属性」，身份维度保持「默认落点」，两者正交。

### 5.4 计税档案分组（B 项，展示层，不改值）

`taxProfile.identity` 的 4 个值 → 在「我的情况」下拉里用 `<optgroup>` 分两段，值一个不改：

```
<option value="">未填</option>
<optgroup label="我自己">  employee 上班族 / freelance 自由职业·副业 / owner 个体户·老板
<optgroup label="企业">    finance 企业财务·代账
```

### 5.5 兼容与降级

| 场景 | 行为 |
|---|---|
| 存量 `euriskoPrefIdentity = 'finance'` | `kindOf()` 解析为 `enterprise`，打开即展开该组并预选，无需重选 |
| 存量非法 / 已废弃 id | `kindOf()` 返回 `''` → 落 `KINDS[0]`；`identityLabel()` 返回 `''` → 界面退回「我是谁」/「未选择」 |
| 注册表缺 `identityKinds`（老页面、测试桩） | 弹窗退回**平铺 6 张**（`drawList` 兜底分支），不白屏 |
| 无痕 / 禁用存储 | 仍只在内存里生效，不报错（`identity-pref` 未改） |

### 9.3 发布链路

```
1) npx jest                    # NODE_OPTIONS=--max-old-space-size=2048 --maxWorkers=2；后台跑 + 日志重定向
```

## 12. 风险与回滚

| 风险 | 处置 |
|---|---|
| 折叠让一半可选卡默认不可见 | 组头带计数 + 组头 desc 直接说明这组是干什么的；默认展开已选组 |
| 老用户语义漂移（executive 从企业侧变自己侧） | 只影响推荐排序，不影响可达性；显示「我自己 · 高管 / 股东」更准 |
| 单测桩与真注册表不一致 | 兜底分支（无 `identityKinds` → 平铺）+ 一条专守兜底的用例 |
| 与 `entity-store` 概念混淆 | kind id 用 `self` / `enterprise`，避开 `person` / `company`；两处文件头写明两条线 |
| 手机端组头 desc 挤成一团 | desc 允许换行、`flex:1`、`min-width:0`；用截图基线比对 7 页 × 2 断点 |
| 误发正式站 | 发布只用 `ops-deploy-beta.ps1`；发布后核对正式站 version.json 仍 1.149.8 |

回滚：`powershell -File tools/ops/ops-deploy-beta.ps1 -Rollback`；数据侧无迁移，回滚无需清理 localStorage。

## 13. 明确不做（留待后续版本）

1. **`taxProfile.identity` 存储值收敛为 self / enterprise** —— 需要迁移脚本 + 双读兼容，且会给「算错没人查得到」开新口子；
2. **纳税主体 `kind` 3 值改 2 值** —— 个体户归自然人还是企业是业务决策，且 `taxpayerType` / `levyMode` 只对经营主体有意义；
3. **留资 `entity_type` 5 值收敛** —— 要动服务端枚举 + prisma 迁移；
4. **工具页分类条两级化（我自己 / 企业 → 5 组）** —— §5.3 已证 5 组不可二分，属另一版信息架构的事；
5. **身份跨设备同步** —— 目前是纯本机偏好，要做需后端字段（User 表无 identity）。
